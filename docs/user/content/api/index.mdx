Script your instance through the same HTTP API the app uses. Signed in with a session cookie, you can do everything the app does; an [API token](/api/tokens) reaches less.

## Base URL and format

Every endpoint lives under `/api/v1` of your instance, such as `http://localhost:8060/api/v1`. Requests and responses are JSON, with camelCase field names.

The API is versioned with Rezepte: `info.version` in `/api/v1/openapi.json` is the version the instance runs. Each release's [changelog](/changelog) page lists API changes.

## Authentication

Programs should use an **API token** (see [API tokens](/api/tokens)):

```bash
curl -H "Authorization: Bearer rzp_..." \
  'http://localhost:8060/api/v1/recipes?limit=5'
```

The browser's **session cookie** works from a script too:

```bash
curl -c cookies.txt -H 'Content-Type: application/json' \
  -d '{"username":"demo","password":"demo1234"}' \
  http://localhost:8060/api/v1/auth/login

curl -b cookies.txt 'http://localhost:8060/api/v1/recipes?limit=5'
```

<Callout type="warn" title="Writes check the Origin header">
  A `POST`, `PUT`, `PATCH` or `DELETE` that sends an `Origin` header must send this instance's host. A request without `Origin`, like the `curl` calls above, passes. Behind a [reverse proxy](/operations/reverse-proxy), forward `Origin` unchanged.
</Callout>

## Errors

Errors are `application/problem+json`:

```json
{
  "title": "Unprocessable Entity",
  "status": 422,
  "detail": "validation failed",
  "errors": [{ "location": "body.title", "message": "expected length >= 1" }]
}
```

## Interactive docs

A running instance serves interactive, try-it-out docs at `/api/v1/docs`. In the app, **Settings → API** links to them and to the raw OpenAPI document. To connect an AI assistant, see [Connect an AI assistant](/api/mcp).
