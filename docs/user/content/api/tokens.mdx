An API token lets a script, a second instance or [an AI assistant](/api/mcp) use your instance without a login form. Only admins can issue tokens, under **Settings → API**.

## Creating a token<Audience role="admin" />

1. Open **Settings → API** and choose **Create token**.
2. Give it a name that says where it will live, such as "MCP on the laptop".
3. Set its access for each area (see [the table below](#what-each-level-allows)). Give it the least it needs; **Create** works only once one area is above **None**.
4. Choose its **Lifetime**: **30 days**, **90 days**, **1 year** or **No expiry**.
5. Choose **Create**.

<Callout type="warn" title="The token is shown once">
  Copy it, then choose **I have saved it**. It cannot be shown again. If you lose it, revoke it and create a new one.
</Callout>

## What each level allows

Each level includes the ones before it.

| Area | **Read** | **Write** | **Delete** |
|---|---|---|---|
| **Recipes** | Search and read recipes, tags and household settings | Create and edit recipes, import | Delete recipes |
| **Accounts** | List people and accounts | Add, change and delete accounts | — |
| **Shopping lists** | Read your lists and their items | Everything the app does with a list, sharing included | — |

With **Recipes: Read**, a token also opens image files. Any token opens the OpenAPI document, so a client can discover the API. An [AI assistant](/api/mcp) needs **Recipes: Read** at least, and does less with lists than the HTTP API.

## Using a token

Send it as a bearer token, in place of the session cookie:

```bash
curl -H "Authorization: Bearer rzp_..." https://your-instance/api/v1/recipes
```

## Who a token acts as

A token acts as the admin who issued it, with that admin's role as it is now, limited by its levels.

- It reaches only the shopping lists its issuer can open: their own and those shared with them.
- It inherits its issuer's rank. An ordinary admin's token with **Accounts: Write** can add and delete members but cannot make anyone an admin; the owner's can (see [People](/guide/users)).
- It stops working the moment its issuer loses the admin role or is deleted.

To give the owner a token that cannot hand out admin rights, create a second admin as a service account and issue the token as them.

<Callout type="warn" title="Deleting members moves their recipes">
  Deleting a member does not delete their recipes. They pass to whoever performed the deletion, which for a token is its issuer.
</Callout>

## Locked recipes

[Editing rights](/guide/editing-rights) do not narrow a token: admins may edit every recipe, locked or not, so a **Recipes: Write** token can too, and a **Recipes: Delete** token can delete every recipe. Only the owner can change the household's editing setting, and only in the browser.

## What a token cannot do

Whatever its levels, a token cannot:

- list, issue or revoke API tokens
- read or change its own account (password, display name, color, photo, email, notifications), or look up which colors are taken
- sign out, or handle sessions in any other way
- change the household settings
- issue or revoke setup links, or disconnect an account from its identity provider
- list, create or revoke public links
- touch the mail settings and test mail, or the sign-in settings
- use push notifications and timer alarms

The [API reference](/api/reference) names the endpoints.

## Revoking a token<Audience role="admin" />

Choose **Revoke** on its tag and confirm. The token stops working immediately.

<Callout type="warn">
  Revoking cannot be undone.
</Callout>

Expired tokens stay in the list, marked **Expired**, until you revoke them. Each tag shows the first characters of its token, so you can match it to a program's configuration.

The list shows your own tokens. Switch on **Everyone in the household** to see every admin's tokens.
