---
title: Members
description: Create accounts, reset passwords and delete members; the owner assigns roles
---

This page is for admins; a "Mitglied" account does not see "Benutzer" in Settings, and is redirected to their own settings if they open its URL directly.

Admins are not all equal here. Every admin looks after the members; admins themselves belong to the instance owner — the account created on the very first start (see [First login](/getting-started/first-login)). Actions you are not allowed to take are simply not shown in the row, so the list already reflects this table:

| | Mitglied | Admin | Inhaber |
| --- | :-: | :-: | :-: |
| Cook, add and edit recipes, upload images | ✓ | ✓ | ✓ |
| Change your own password | ✓ | ✓ | ✓ |
| See the member list | – | ✓ | ✓ |
| Add a member, reset a member's password, remove a member | – | ✓ | ✓ |
| Add an **admin**, reset an admin's password, remove an admin | – | – | ✓ |
| Hand out the "Admin" role or take it back | – | – | ✓ |
| Issue [API tokens](/api/tokens) | – | ✓ | ✓ |
| Remove or demote the **Inhaber**, or reset their password | – | – | – |
| Delete your own account | – | – | – |

There is exactly one Inhaber and it never changes: the role cannot be handed to anyone, which is why "Inhaber" is not offered when you create an account or change a role.

<Steps>
  <Step>

    ### Open member management

    Go to "Einstellungen" → "Benutzer". The list is sorted by name. On a wide screen the "Name" and "Rolle" column headings sort it: click one to sort by it, click the same one again to turn the whole order around, names included. "Rolle" groups by rank, Inhaber first, then Admin, then Mitglied, and sorts by name inside each group. On a phone the rows are cards without headings and stay sorted by name.

  </Step>
  <Step>

    ### Add a member

    Click "Benutzer anlegen" and fill in a username, a password (8–128 characters) and a role.

    <Screenshot name="user-create" caption="Creating a new member" />

    "Admin" can manage users and everything a member can; "Mitglied" cooks and edits recipes. The "Admin" option is offered to the owner only — any other admin creates members.

  </Step>
  <Step>

    ### Change a role

    Use the "Rolle" select in a member's row to switch them between "Admin" and "Mitglied". Only the owner has this select; for every other admin the role is shown as plain text.

  </Step>
  <Step>

    ### Reset a password

    "Passwort zurücksetzen" sets a new password for that member and signs them out on every device. Resetting another admin's password is the owner's alone, and nobody resets their own password here — that is "Passwort ändern" in your own settings, which asks for the current one.

  </Step>
  <Step>

    ### Remove a member

    Delete their row. Their recipes are not removed — see the note below.

  </Step>
</Steps>

<Callout type="info" title="Good to know">
  The owner's row is marked "Inhaber" and carries no actions at all: that account cannot be deleted, cannot lose its admin rights, and its password cannot be reset from here by anyone, the owner included. So the household always keeps at least one admin. You also cannot delete your own account from this page.
</Callout>

<Accordions type="single">
  <Accordion title="What happens to a deleted member's recipes">
    They are not deleted — they are transferred to the admin who performed the deletion.
  </Accordion>
  <Accordion title="Members and this page">
    A "Mitglied" account that navigates directly to this page's URL is sent to their own settings instead; the same rule is enforced by the API, so this is purely a courtesy redirect, not the only protection.
  </Accordion>
</Accordions>
