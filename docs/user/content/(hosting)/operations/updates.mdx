---
title: Updates
description: How to update Rezepte and check which version is running
---

Update Rezepte by replacing the image or binary and starting it again. Pending database migrations run automatically on that start, before Rezepte serves requests.

Before you update, read the release's page in the [Changelog](/changelog). If the release needs anything from you, the page opens with **Before you upgrade**. Every version is on the [releases page](https://github.com/s-frei/rezepte/releases).

<Callout type="warn" title="Back up first; there is no downgrade">
  [Back up your data](/operations/data-and-backup) before updating. Once migrations have run, you cannot go back to an older version, and a failed migration is easier to recover from a backup than to fix in place.
</Callout>

## Update

<Tabs groupId="install" persist items={['Docker', 'Binary']}>
  <Tab value="Docker">

    ```bash
    docker compose pull
    docker compose up -d
    ```

  </Tab>
  <Tab value="Binary">

    Download the new archive from the [latest release](https://github.com/s-frei/rezepte/releases/latest), replace the installed binary and restart it: `sudo systemctl restart rezepte` for the [systemd unit](/getting-started/binary#run-as-a-systemd-service).

  </Tab>
</Tabs>

## Confirm the new version is running

```bash
curl -s http://localhost:8060/healthz
```

It answers `{"status":"ok","version":"1.4.0"}` and needs no login, so a monitoring check can use it too. You can also ask the binary directly:

```bash
rezepte --version                                # the binary
docker compose exec rezepte /rezepte --version   # inside the container
```

Docker watches the instance on its own: `docker ps` shows the container as `healthy` once it serves, and `unhealthy` if it stops answering.

```bash
docker ps
# STATUS
# Up 2 minutes (healthy)
```

The first 30 seconds after a start do not count against it, while migrations run.
