Let people sign in with Google or your own OpenID Connect provider, such as Authelia, Authentik, Pocket ID, Keycloak or Dex. The login page then shows "Continue with …" under the password form.

## What it does and what it does not

- **It only signs in people who already have an account.** A provider account nobody connected gets "not connected to Rezepte yet", never a new account. So anyone with a Google account still cannot get into your household.
- **Accounts are matched only by the provider's account ID**, never by email address.
- **One provider per instance.** GitHub, Facebook and other providers that are not OpenID Connect do not work.
- **Roles stay in Rezepte.** The provider says who somebody is; **People** decides what they may do.
- **Signing out of Rezepte ends only the Rezepte session.** Signing out at the provider does not sign anybody out of Rezepte.
- **If the provider is down, passwords keep working.**

## Configure it

Register Rezepte at your provider as a web application with this redirect URI:

```text
https://<your Rezepte address>/api/v1/auth/oidc/callback
```

Set `REZEPTE_PUBLIC_URL` to the address people open Rezepte at, exactly as in the browser, without a path ([Configuration](/getting-started/configuration)). It must match the address you registered at the provider. Then tell Rezepte about the provider, in the app or with environment variables.

### In Rezepte<Audience role="owner" />

Open **Settings → Sign-in**, copy the redirect URI from the card and press **Set up sign-in**:

| Field | Value |
| --- | --- |
| **Issuer URL** | The provider's address, checked on save |
| **Client ID** | From the provider |
| **Client secret** | From the provider; leave empty for a public client |
| **Button name** | Such as "Google", for "Continue with Google" |

The change applies at once, without a restart.

<Screenshot name="sign-in-card" caption="The Sign-in card once a provider is set up" />

- **Edit** keeps a saved secret when you leave the field empty, but only for the same issuer and client ID.
- **Turn off** removes the settings, secret included.
- Connections stay saved and apply again if you set up the same provider again.

<Callout type="warn" title="Turning off or switching providers">
  People connected to the old provider can no longer sign in with it. Anyone without a password then needs a setup link. Rezepte asks first and lists them under "connected accounts".
</Callout>

### With environment variables

Set these instead, as plain environment variables or under `environment:` in `docker-compose.yaml` ([Docker](/getting-started/docker)):

<Tabs items={['Environment variables', 'docker-compose.yaml']}>
  <Tab value="Environment variables">

    ```bash
    REZEPTE_PUBLIC_URL=https://rezepte.example.org
    REZEPTE_OIDC_ISSUER=https://accounts.google.com
    REZEPTE_OIDC_CLIENT_ID=<client ID>
    REZEPTE_OIDC_CLIENT_SECRET=<client secret>
    REZEPTE_OIDC_NAME=Google
    ```

  </Tab>
  <Tab value="docker-compose.yaml">

    ```yaml title="docker-compose.yaml"
    services:
      rezepte:
        environment:
          REZEPTE_ADMIN_PASSWORD: change-me-now
          REZEPTE_PUBLIC_URL: https://rezepte.example.org
          REZEPTE_OIDC_ISSUER: https://accounts.google.com
          REZEPTE_OIDC_CLIENT_ID: <client ID>
          REZEPTE_OIDC_CLIENT_SECRET: <client secret>
          REZEPTE_OIDC_NAME: Google
    ```

  </Tab>
</Tabs>

The variables win over anything saved in Rezepte, and the card reads "Set by the server". To change them, edit the variables and restart. Without `REZEPTE_OIDC_NAME`, the button reads "Continue with single sign-on".

<Tabs items={['Google', 'Authelia']}>
  <Tab value="Google">

    In the Google Cloud Console, pick or create a project in the top bar. The links below then open the right page of it.

    1. On the [overview](https://console.cloud.google.com/auth/overview), start the setup: the app name (for example "Rezepte") and your email address.
    2. Under [Audience](https://console.cloud.google.com/auth/audience), choose "External" and press "Publish app". Rezepte asks only for `openid` and `email`, so Google needs no verification. Only connected accounts get in. In "Testing" instead, only the Google accounts you list as test users can sign in.
    3. Under [Clients](https://console.cloud.google.com/auth/clients), create a client of type "Web application" and add `https://<your Rezepte address>/api/v1/auth/oidc/callback` as an authorized redirect URI.
    4. Enter the client ID and secret, `https://accounts.google.com` as the issuer and "Google" as the button name, in Settings → Sign-in or as the variables above.

  </Tab>
  <Tab value="Authelia">

    Add a client to Authelia's `identity_providers.oidc.clients`:

    ```yaml
    - client_id: rezepte
      client_name: Rezepte
      client_secret: '$pbkdf2-sha512$...'  # the hashed secret
      public: false
      authorization_policy: one_factor
      require_pkce: true
      pkce_challenge_method: S256
      redirect_uris:
        - https://rezepte.example.org/api/v1/auth/oidc/callback
      scopes: [openid, email]
      response_types: [code]
      grant_types: [authorization_code]
      token_endpoint_auth_method: client_secret_basic
    ```

    Then enter your Authelia address (such as `https://auth.example.org`) as the issuer, `rezepte` as the client ID, the plain secret and "Authelia" as the button name, in Settings → Sign-in or as the variables above.

  </Tab>
</Tabs>

## How people connect

- **An existing account:** sign in with the password, open "Settings" and press **Connect** on the "Sign-in" row. From then on the login button signs you in.
- **A new account:** the [setup link](/guide/users) offers "Continue with …" above the password form.
- **Disconnecting:** the "Sign-in" row in Settings disconnects, but only once the account has a password. An admin can disconnect anyone under [People](/guide/users#disconnect-single-sign-on) and then send a setup link.

If the login page says the account is not connected yet, sign in with the password and connect it, or ask an admin for a setup link.
