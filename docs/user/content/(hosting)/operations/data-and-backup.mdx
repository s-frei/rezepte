title: Data and backup

Back up one directory and you have everything: the data directory (`REZEPTE_DATA_DIR`, `/data` in the Docker image).

| Path | Holds |
| --- | --- |
| `rezepte.db` | The database: recipes, comments, accounts, sessions, API tokens, shopping lists, public links and all settings |
| `rezepte.db-wal`, `rezepte.db-shm` | The newest writes, not yet folded into `rezepte.db` |
| `images/` | Recipe and comment photos |
| `avatars/` | Profile photos |

Back up the three `rezepte.db*` files together or not at all. Back up `avatars/` too, or every account comes back with its initial instead of its photo.

<Callout type="warn" title="Backups contain secrets">
  A mail password set under [Settings → Email](/guide/mail) and a client secret set under [Settings → Sign-in](/operations/single-sign-on) are stored in the database unencrypted. Keep backups as private as those secrets. Values set with `REZEPTE_SMTP_PASSWORD` or `REZEPTE_OIDC_CLIENT_SECRET` stay out of the database.
</Callout>

A comment photo added to the recipe photos is a hard link to the same files. Copy with `rsync -H`, as below, so a backup does not store it twice.

To pass recipes to another instance instead, see [Import and export](/guide/import-export).

## Backing up

<Tabs groupId="install" persist items={['Docker', 'Binary']}>
  <Tab value="Docker">

    Stop Rezepte for a few seconds and pack the data directory into one archive, from a throwaway container:

    ```bash
    docker compose stop rezepte
    docker run --rm --volumes-from "$(docker compose ps -aq rezepte)" \
      -v "$PWD/backups:/backup" alpine:3 \
      tar czf "/backup/rezepte-$(date +%F).tar.gz" -C /data .
    docker compose start rezepte
    ```

    Run it next to your `docker-compose.yaml`; the archive lands in `backups/`. It works for a named volume and a bind mount alike.

    Started with `docker run --name rezepte` instead of compose? Use `docker stop rezepte` and `docker start rezepte`, and `--volumes-from rezepte`.

    With a bind mount, you can instead back up the host directory while Rezepte keeps running, with the commands in the Binary tab. Run them as UID 65532, which owns the files.

  </Tab>
  <Tab value="Binary">

    With the binary, back up while Rezepte keeps running. You need the `sqlite3` tool on the host:

    ```bash
    sqlite3 /var/lib/rezepte/rezepte.db ".backup /backups/rezepte-$(date +%F).db"
    rsync -aH --exclude 'rezepte.db*' /var/lib/rezepte/ /backups/files/
    ```

    `sqlite3` writes one consistent file; `rsync` copies everything else in the data directory.

    <Callout type="warn">
      Run both as the account that owns the data directory: `rezepte` in the [systemd unit](/getting-started/binary#run-as-a-systemd-service). Run as root, SQLite can leave files next to the database that Rezepte cannot write.
    </Callout>

  </Tab>
</Tabs>

<Callout type="warn">
  Never copy `rezepte.db` with `cp` while Rezepte runs: the copy can miss recent writes or catch the database mid-write. Use `sqlite3 .backup`, or stop Rezepte first.
</Callout>

## Restoring

<Callout type="warn">
  A restore replaces everything in the data directory. Anything changed since the backup is lost.
</Callout>

<Tabs groupId="install" persist items={['Docker', 'Binary']}>
  <Tab value="Docker">

    Stop Rezepte, empty the volume, unpack the archive and give the files back to UID 65532:

    ```bash
    docker compose stop rezepte
    docker run --rm --volumes-from "$(docker compose ps -aq rezepte)" \
      -v "$PWD/backups:/backup:ro" alpine:3 \
      sh -c 'rm -rf /data/* \
        && tar xzf /backup/rezepte-2026-01-31.tar.gz -C /data \
        && chown -R 65532:65532 /data'
    docker compose start rezepte
    ```

    Replace `rezepte-2026-01-31.tar.gz` with your archive's name.

  </Tab>
  <Tab value="Binary">

    1. Stop Rezepte.
    2. Replace `rezepte.db` with the backup, and delete any leftover `rezepte.db-wal` / `rezepte.db-shm` next to it — they belong to the database you replaced, not to the backup.
    3. Copy the backed-up files back into the data directory: `rsync -aH /backups/files/ /var/lib/rezepte/`.
    4. Give the data directory back to the account Rezepte runs as, for example `chown -R rezepte:rezepte /var/lib/rezepte`.
    5. Start Rezepte again.

  </Tab>
</Tabs>
