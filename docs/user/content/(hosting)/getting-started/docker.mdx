Run the image `ghcr.io/s-frei/rezepte` (`linux/amd64`, `linux/arm64`). It listens on port 8060 and keeps everything under `/data`.

<Tabs items={['docker compose', 'docker run']}>
  <Tab value="docker compose">

    This is the repository's [`docker-compose.yaml`](https://github.com/s-frei/rezepte/blob/main/docker-compose.yaml):

    <include lang="yaml" meta='title="docker-compose.yaml"'>../../../../../docker-compose.yaml#compose</include>

    ```bash
    docker compose up -d
    ```

  </Tab>
  <Tab value="docker run">

    ```bash
    docker run -d --name rezepte -p 8060:8060 --stop-timeout 150 \
      -e REZEPTE_ADMIN_PASSWORD=change-me-now \
      -v "$PWD/data:/data" \
      ghcr.io/s-frei/rezepte:latest
    ```

  </Tab>
</Tabs>

## Image tags

`latest` is the newest stable release. To run another version, use its tag in place of `latest`. Every version is on the [releases page](https://github.com/s-frei/rezepte/releases), every tag on the [package page](https://github.com/s-frei/rezepte/pkgs/container/rezepte).

Each image carries an SPDX SBOM and build provenance, so Trivy and Grype scan it straight from the registry. The web app's packages are in the release's `.spdx.json` files ([Download](/getting-started/binary#download)).

## Bind mounts

The container runs as UID 65532. Before the first start, make a bind-mounted `./data` writable by it:

```bash
mkdir -p data
chown 65532:65532 data
```

A named volume, as in the compose file, needs nothing.

## Updating

Run `docker compose pull` and `docker compose up -d`. See [Updates](/operations/updates) before you do.

## Demo mode

Run `docker run --rm -p 8060:8060 ghcr.io/s-frei/rezepte:latest --demo` for sample data that is gone when the container stops. See [`--demo`](/getting-started/configuration#--demo) for the logins.
