`REZEPTE_ADMIN_USER` and `REZEPTE_ADMIN_PASSWORD` are read only on the first start; see [First login](/getting-started/first-login#the-owner-account).

`REZEPTE_OIDC_*` is optional: the owner can set up the provider in Settings → Sign-in instead. Set the variables and they win, and the card reads "Set by the server". `REZEPTE_OIDC_ISSUER`, `REZEPTE_OIDC_CLIENT_ID` and `REZEPTE_PUBLIC_URL` go together: set one without the others and Rezepte refuses to start. See [Single sign-on](/operations/single-sign-on).

## Mail

Set `REZEPTE_SMTP_HOST`, `REZEPTE_SMTP_FROM` and `REZEPTE_PUBLIC_URL` (plus the username and password from your mail provider) to turn mail on. Without mail, there is no **Forgot password?** and no address confirmation; [Mail](/guide/mail) lists what Rezepte sends.

- Rezepte refuses to start when `REZEPTE_SMTP_HOST` is set without `REZEPTE_SMTP_FROM` or `REZEPTE_PUBLIC_URL`, or with an unknown `REZEPTE_SMTP_SECURITY`.
- With `starttls`, Rezepte never falls back to an unencrypted connection. A server that does not offer it is an error.
- Set `TZ` to your time zone (`TZ: Europe/Berlin` in the compose file). Without it, times use the server's zone, UTC in the Docker image.
- While `REZEPTE_SMTP_HOST` is set, the **Email** card in Settings shows the values and cannot change them. Change the variables and restart. Leave it unset to set mail up in the app ([Mail](/guide/mail)).

<Callout type="info">
  For mail to reach inboxes rather than spam, publish the SPF and DKIM records your provider documents for the sender's domain.
</Callout>

## Command-line flags

### `--demo`

```bash
rezepte --demo
```

Fills an empty data directory with twelve sample recipes, most with photos, in the language of `REZEPTE_LOCALE` (English where there is no sample set). On an instance that already has recipes, it does nothing and starts normally.

If `REZEPTE_ADMIN_PASSWORD` is unset, it also creates these accounts and prints their logins:

| Login | Password | State |
| --- | --- | --- |
| `demo` | `demo1234` | The owner |
| `mila`, `jonas` | `mila1234`, `jonas1234` | Members who wrote and marked a few recipes |
| `noah` | none | An open setup link, as for someone not yet signed in |

The demo accounts hold a few public links, paused until you switch public sharing on ([Public links](/guide/sharing#public-links)).

### `--reset-superadmin-password`

```bash
REZEPTE_ADMIN_PASSWORD='the new password' rezepte --reset-superadmin-password
```

Sets the owner's password to `REZEPTE_ADMIN_PASSWORD`, signs that account out on every device and exits without starting the server. An empty value is an error. Start Rezepte normally afterwards and log in with the new password.

Use it only for the owner; everyone else's password is reset in [People](/guide/users).

### `--version`

```bash
rezepte --version
```

Prints the version and exits. See [Updates](/operations/updates#confirm-the-new-version-is-running) for a running instance.

### `--healthcheck`

```bash
rezepte --healthcheck
```

Asks the instance on `REZEPTE_ADDR` whether it is serving and exits: `0` if it answered, non-zero with a reason if not. It touches neither the database nor the data directory, so it is safe beside a live instance. The Docker image uses it as its `HEALTHCHECK`; a systemd watchdog or monitoring check can too.

## Logging

`REZEPTE_LOG_FORMAT=text` (the default) writes one line per event: time, level (`DBG`, `INF`, `WRN`, `ERR`) and message.

```text
10:00:00 INF http: listening addr=:8060 url=http://localhost:8060
```

The level is colored only in a terminal, so files and journald get plain text.

| Setting | Effect |
| --- | --- |
| `NO_COLOR=1` | Color off everywhere |
| `FORCE_COLOR=1` | Color on without a terminal |
| `tty: true` on the compose service | Colors in `docker compose logs` |

`REZEPTE_LOG_FORMAT=json` writes one uncolored JSON object per line, for a log collector:

```json
{"time":"2026-09-18T10:00:00.000+02:00","level":"INFO","msg":"http: listening","addr":":8060","url":"http://localhost:8060"}
```
