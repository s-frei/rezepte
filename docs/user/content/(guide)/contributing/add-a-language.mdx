---
title: Add a language
description: Translate the interface into another language and contribute it
---

Translate Rezepte's interface into your language and contribute it. It takes no programming: you edit four files and run a few commands. Recipes themselves are never translated.

## What you need

- A clone of the [repository](https://github.com/s-frei/rezepte).
- [mise](https://mise.jdx.dev), which installs every other tool the project uses. Run `mise run setup` once in the clone.

## Steps

The examples use French, `fr`. Use your language's code instead.

<Steps>
  <Step>

    ### Name the language
    Add its [language code](https://en.wikipedia.org/wiki/List_of_ISO_639_language_codes) to `locales` in `service/internal/i18n/locales.json`:

    ```json title="service/internal/i18n/locales.json"
    {
        "baseLocale": "en",
        "locales": ["en", "de", "fr"]
    }
    ```

    Leave `baseLocale` as it is. Every text falls back to English.

  </Step>
  <Step>

    ### List the recipe words
    Importing a recipe needs to know the words recipes in your language use.

    1. Copy `service/internal/recipeimport/lang_en.go` to `lang_fr.go`.
    2. In the copy, rename `english` to `french`. Replace the English words with yours, as the comments in `lang.go` explain: units ("c. à s.", "pincée"), the headings above ingredients and steps ("Ingrédients", "Préparation"), and words like "à volonté".
    3. Add `french` to `var languages` in `lang.go`.

    If you have never written Go tests, say so in the pull request, and a maintainer adds them.

  </Step>
  <Step>

    ### Translate the texts
    Copy `frontend/messages/en.json` to `frontend/messages/fr.json` and translate every value on the right-hand side:

    ```json title="frontend/messages/fr.json"
    "overview_headline": "Que cuisine-t-on aujourd'hui ?",
    ```

    - Keep every key on the left exactly as it is.
    - Keep every placeholder in curly braces, such as `{count}`, exactly as it is. You may move it within the sentence.
    - Translate every entry. The check fails on any that are missing.
    - The keys starting with `mail_` are the mails Rezepte sends.

    A few values are not sentences:

    | Key | What to write |
    |---|---|
    | `editor_unit_options` | The units cooks in your language use, comma-separated, in their usual abbreviations. German has `TL`, `EL`, `Bund`, `Zehe` and no `cup`. |
    | `time_units_seconds`, `time_units_minutes`, `time_units_hours` | Every spelling of the unit, separated by `\|`, full words first. German: `Minuten\|Minute\|Min.\|Min` |
    | `time_words_range`, `time_words_and` | The words in "10 to 15 minutes" and "1 hour and 20 minutes" |
    | `import_example` | An example recipe, using the headings your `lang_fr.go` knows. The check imports it. |

  </Step>
  <Step>

    ### Check and look at it
    ```bash
    mise run //service:generate
    mise run check
    mise run //docs/user:openapi
    RZP_DEMO_LOCALE=fr mise run demo
    ```

    1. `generate` copies your mail texts to `service/internal/mail/messages/fr.json`. Without it, `check` fails.
    2. `check` finds missing texts and placeholders.
    3. `openapi` adds your language to the API reference.
    4. `demo` starts a demo instance. Open the address it prints and log in as `demo` / `demo1234`.

    The demo recipes stay in English unless you add sample recipes in your language. That is optional.

  </Step>
  <Step>

    ### Contribute it
    Open a pull request with:

    - the new `fr.json` and `lang_fr.go`
    - the changed `locales.json` and `lang.go`
    - the generated `service/internal/mail/messages/fr.json` and the updated API reference

  </Step>
</Steps>
