Rezepte can mail the setup link to the people you invite, so you do not have to pass it on yourself. With mail set up it also sends a link for a new password to anyone who forgot theirs (or a sign-in hint to someone who signs in with an identity provider), a link to confirm an email address, notices when your password, your address or your ways to sign in change, and [notifications](/guide/notifications) about comments, new recipes, tasty marks and accepted invitations, which are on until you switch them off. It needs an SMTP server to send through — the one your mail provider lists under "SMTP" or "set up a mail program" — and `REZEPTE_PUBLIC_URL` set, so the link in the mail points back to your Rezepte (see [Configuration](/getting-started/configuration)). Without mail, you get every setup link on screen and pass it on yourself, the login page offers no **Forgot password?**, and email addresses stay unconfirmed.

## Set up mail<Audience role="owner" />

The owner finds the **Email** card on its own page, **Settings → Email**, which nobody else sees. It is a letterhead: who mail comes from, which server it goes through and how it signs in, with a stamp saying whether Rezepte is sending.

<Screenshot name="mail-card" caption="The Email card once mail is on" />

<Steps>
  <Step>

    ### Open the setup

    Click "Set up mail" — or "Edit" when it is already set up. The window has three parts.

    <Screenshot name="mail-dialog" caption="Setting up mail" />

  </Step>
  <Step>

    ### Fill in the parts

    **Sender**: the address mail comes from and the name people see in their inbox; a line under the name shows how it will look. **Sign-in**: the username and password of your mail provider; leave both empty for a server that needs none. A saved password stays when you leave the field empty, but only for the same server and username; change either and type the password again. **Server**: its address and port, and the encryption. STARTTLS usually goes with port 587 and TLS with 465; "None" is only for a server in your own network.

  </Step>
  <Step>

    ### Send a test mail

    Above "Save", the window has a "Send a test mail to" field with your own address filled in. "Send with these values" tries the values as they are, before you save them, and tells you right under the field what the server answered. Fix what it complains about, then "Save". Saving does not connect to the server; the test does.

  </Step>
</Steps>

On the card, the same field sits under the letterhead, filled in with your own address; change it to test another inbox. "Send" (or Enter) shows the result right under it: "Test mail sent to …", or the server's own reply when it refuses. This is also where to look when an invitation did not arrive, since only the owner sees what went wrong.

"Turn off" asks first, then clears the settings, and the stored password with them: a saved password can only be removed this way. When the server is set with `REZEPTE_SMTP_*` variables, the stamp reads "Set by the server", the settings cannot be changed here, and only the test works.

## What a person receives

An invitation from the admin's name: "Hi Lena, Mila created an account for you on Rezepte", a button "Set up account" and the link spelled out beneath it, for mail programs that hide buttons. It is in the language of the invited account, works once and is valid for 7 days. A setup link for an account that can already sign in, for someone who lost their password or their sign-in provider, says instead that the admin sent a setup link for their account, with a button "Open setup link". Opening it greets the person, lets them choose a password and signs them in — and that confirms their address, as long as it is still the one the mail went to.

<Screenshot name="setup-link-dialog" caption="The admin sees where the link went" />

Mails go out on their own, too:

- **A link for a new password**, when someone asks for one on the login page. It names the account, is valid for 1 hour and works once. The button "Set a new password" opens a page titled "A new password for …", where the person types the new password twice and "Save password" signs them in.
- **A sign-in hint**, instead, for an account that has no password because it signs in with an identity provider: it names the provider and says to ask an admin for a setup link if access to it is lost.
- **A confirmation**, when an address is entered or changed in a profile or by an admin (who is named in it). It names the account too, so accounts sharing an address can tell their mails apart. It is valid for 7 days. The link opens a page that confirms the address right away and says "Address confirmed"; it never signs anyone in.

## Notification mails

Four mails tell people what happened in the household. Each of them can also come as a push notification, and you switch each on or off for mail and push separately: see [Notifications](/guide/notifications).

- **A new comment** on a recipe you follow, meaning one that is yours (you added it, or it came to you from an account an admin deleted) or that you commented on. It names who wrote it, quotes the comment, shows its photos and has a button that opens the recipe's comments. You never get a mail for your own comment, and each comment is its own mail.
- **New recipes**, once a day at the hour the owner sets under [Settings → Notifications](/guide/notifications#choose-what-comes): one mail with the recipes the others added since the last one, never your own. The first six come as cards with their photo, who added it, servings and time, and a button to open the recipe; the next 30 are listed below by name, and any beyond that are counted. A recipe waits for the next day's mail until it is an hour old, so the photo and the last corrections usually make it in. Recipes that arrive by importing an archive are not announced. On a day nobody else added a recipe, no mail comes.
- **Tasty**, when someone marks a recipe of yours tasty: "… went down well", with their picture and a button to the recipe. It goes out about a minute after the mark, and not at all when the mark was taken back by then.
- **An accepted invitation**, for admins and the owner. When someone you invited opens their setup link and sets up the account, the admin who sent the link hears about it, with a button to the list of people.

Only an address that is confirmed gets them. Your choices stay when mail is turned off for a while.

### Unsubscribing from a mail

Every mail you can switch off ends with an unsubscribe link, and your mail app's own "Unsubscribe" button does the same. The button switches off just that kind of mail. The link opens a page that works without signing in, so it also works on a phone where you are not logged in.

<Screenshot name="unsubscribe" caption="The page an unsubscribe link opens" />

The page offers to switch off that kind of mail or the whole group, and "Undo" takes it back right away, turning on again only what that click turned off. Either way only the mail is switched off; push notifications stay as you set them. When the mails are off already, the page says "Already unsubscribed" instead. A link is good for 90 days; after that the page says it no longer works, and **Settings → Notifications** is the way to change it.

## Security notices always come

A mail that says your password was set or changed, your email address was changed or removed, or a sign-in method was added is a security notice: you cannot switch it off, and it carries no unsubscribe link. It exists so you notice when someone else changes your account. It goes only to a confirmed address; the notice about a changed address goes to the old one and shows the new one only in part. The time in a notice is in the server's time zone, UTC unless the server sets `TZ` (see [Configuration](/getting-started/configuration)).

- **Password changed.** It says how: by you, by an admin (named), with a reset link or a setup link, or from the server's command line. For an account that signed in only through an identity provider until then, it says a password was set. The button opens the page for a new password; the owner's notice has no button and points to the server's command line instead (`rezepte --reset-superadmin-password`).
- **Email address changed or removed.** It goes to the address the account had before.
- **Sign-in method added.** When someone links an identity provider to an account that could already sign in, in the profile or with a setup link: it names the provider, when, and the admin whose setup link was used. If it wasn't you, sign in, remove the sign-in method in your profile and change your password; if you can't sign in, tell an admin.

## When a mail does not arrive

- The window after "Create and send link" or "Send link" says "Mail to … could not be sent" when the server refused it. The account and the link exist anyway: copy the link and pass it on yourself.
- Rezepte waits at most 10 seconds for the server. A wrong port or a server that does not answer shows up as a failed send, not as a stuck window.
- A mail that was accepted but never shows up is the mail provider's business: look in the spam folder, and check that the sender domain has the SPF and DKIM records the provider documents.
- Only the owner sees the server's reply, through the test mail. Admins only learn that sending failed.
