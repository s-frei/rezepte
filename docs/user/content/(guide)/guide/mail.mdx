With mail set up, Rezepte sends:

- setup links to the people you invite
- a link for a new password, from **Forgot password?** on the login page
- a link to confirm an email address
- [security notices](#security-notices-always-come) when a password, address or sign-in method changes
- [notifications](/guide/notifications) about comments, new recipes and more

You need an SMTP server (your mail provider lists it under "SMTP") and `REZEPTE_PUBLIC_URL` set, so links point back to your Rezepte. See [Configuration](/getting-started/configuration).

Rezepte works without mail too. You pass setup links on yourself, the login page has no **Forgot password?**, and email addresses stay unconfirmed.

## Set up mail<Audience role="owner" />

Only the owner sees **Settings → Email**.

<Screenshot name="mail-card" caption="The Email card once mail is on" />

<Steps>
  <Step>

    ### Open the setup

    Choose "Set up mail", or "Edit" when it is already set up.

    <Screenshot name="mail-dialog" caption="Setting up mail" />

  </Step>
  <Step>

    ### Fill in the parts

    | Part | What to enter |
    | --- | --- |
    | **Sender** | The address mail comes from and the name people see in their inbox. |
    | **Sign-in** | Your mail provider's username and password. Leave both empty for a server that needs none. |
    | **Server** | Address, port and encryption: STARTTLS usually with port 587, TLS with 465. "None" is only for a server in your own network. |

    A saved password stays when you leave its field empty, but only for the same server and username. Change either and type the password again.

  </Step>
  <Step>

    ### Send a test mail

    Under "Send a test mail to", choose "Send with these values". The answer from the server shows right under the field. Fix what it complains about, then save. Saving alone does not connect to the server.

  </Step>
</Steps>

The card has the same test field, to try another inbox later. "Turn off" asks first, then clears the settings and the stored password. When the server is set with `REZEPTE_SMTP_*` variables, the stamp reads "Set by the server" and only the test works.

## What a person receives

| Mail | When | Valid for |
| --- | --- | --- |
| **Invitation** | An admin creates an account with a setup link and an address. It comes in the invited account's language. | 7 days, once |
| **Setup link** | An admin sends a new setup link, for example after a lost password or sign-in provider. | 7 days, once |
| **A link for a new password** | Someone uses **Forgot password?** on the login page. | 1 hour, once |
| **A sign-in hint** | The same, for an account without a password. It names the provider and says to ask an admin for a setup link. | – |
| **A confirmation** | An address is entered or changed, in a profile or by an admin. | 7 days |

Using a setup link lets the person choose a password, signs them in and confirms their address, as long as it is still the one the mail went to. A confirmation link only confirms the address; it never signs anyone in.

## Notification mails<NewIn release="v1.3.0" />

Which notifications exist, and how to switch each one for mail and push, is on [Notifications](/guide/notifications). Only a confirmed address gets them. The mails show:

- **A new comment**: who wrote it, the comment with its photos, and a button to the recipe's comments. Each comment is its own mail.
- **New recipes**: one mail a day with the recipes the others added. The first six come as cards, the next 30 by name, the rest as a count. A recipe waits for the next day's mail until it is an hour old. Recipes from an imported archive are not announced.
- **Tasty**: who marked your recipe tasty, with a button to the recipe.
- **A shopping list invitation**: who invites you to which list, with a button to your shopping lists.
- **Invitation accepted**: someone set up their account with your setup link. It goes to the admin who created the link, with a button to the list of people.

Your choices stay when the owner turns mail off for a while.

### Unsubscribing from a mail

Every mail you can switch off ends with an unsubscribe link. Your mail app's "Unsubscribe" button switches off just that kind of mail.

The link opens a page that works without signing in. It switches off that kind of mail or the whole group, and "Undo" takes it back. Push notifications stay as you set them. A link works for 90 days; after that, use **Settings → Notifications**.

## Security notices always come

These mails cannot be switched off and have no unsubscribe link. They go only to a confirmed address. Times are in the server's time zone, UTC unless the server sets `TZ`.

- **Password changed** or set: it says how, by you, an admin (named), a reset or setup link, or the server's command line.
- **Email address changed or removed**: it goes to the old address and shows the new one only in part.
- **Sign-in method added**: an identity provider was linked to your account. It names the provider and the admin whose setup link was used.

<Callout type="warn" title="A change you did not make">
  Sign in, remove any sign-in method you do not know in your [profile](/guide/settings#profile) and change your password. If you cannot sign in, tell an admin. The owner's password notice points to the server's command line instead (`rezepte --reset-superadmin-password`, see [First login](/getting-started/first-login)).
</Callout>

## When a mail does not arrive

| Symptom | Fix |
| --- | --- |
| "Mail to … could not be sent" after "Create and send link" or "Send link" | The account and link exist anyway. Copy the link and pass it on yourself. |
| A send fails after a short wait | Check the port and server address. Rezepte waits at most 10 seconds for the server. |
| The mail was accepted but never shows up | Look in the spam folder. Check that the sender domain has the SPF and DKIM records your provider documents. |
| You need to know why it failed | Only the owner sees the server's reply, through the test mail on **Settings → Email**. Admins only learn that sending failed. |
