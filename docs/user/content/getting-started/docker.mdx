The image is published at `ghcr.io/s-frei/rezepte` for `linux/amd64` and `linux/arm64`. It listens on port 8060 and stores everything — the SQLite database and uploaded photos — under `/data`, owned by UID 65532 (the distroless `nonroot` user the container runs as).

    ```bash
      -v "$PWD/data:/data" \
      ghcr.io/s-frei/rezepte:latest
    ```

## Bind mounts

The container runs as the nonroot user (UID 65532), so a bind-mounted `./data` directory must be writable by that UID before the first start:

```bash
mkdir -p data
chown 65532:65532 data
```

A named volume (as in the compose file above) does not need this — Docker creates it already owned by the container's user.

## Updating

```bash
docker compose pull
docker compose up -d
```

Migrations run automatically the next time the container starts, and `curl -s http://localhost:8060/healthz` reports the version now running; see [Updates](/operations/updates).

## Demo mode

Start the image with sample data instead of mounting real data:

```bash
docker run --rm -p 8060:8060 ghcr.io/s-frei/rezepte:latest --demo
```

Open `http://localhost:8060` and log in as **`demo`** / **`demo1234`**. Without a volume nothing persists — the sample recipes and photos disappear when the container stops.
