title: Commits and branches
description: Semantic commit messages, short titles, develop/main
---

Format: `type(scope): summary` following [semantic commit messages](https://gist.github.com/joshbuchea/6f47e86d2510bce28f8e7f42ae84c716).

| Type | Use for |
|---|---|
| `feat` | new user-facing capability |
| `fix` | bug fix |
| `docs` | documentation only (including `docs/memory`) |
| `chore` | tooling, dependencies, config |
| `refactor` | code change without behaviour change |
| `test` | tests only |
| `style` | formatting only |

Scopes: `service`, `frontend`, `docs`, or none.

<Callout type="warn" title="Hard rules">

  - Title at most 70 characters, imperative mood, no trailing period.
  - Body only when the title cannot explain the why.
  - No `Co-Authored-By` or tool trailers.
  - Never commit `docs/superpowers/`.

</Callout>

Branches: work on `develop`, releases merge to `main`.
