---
title: Run the app locally
description: Dev servers, builds and the check gate
---

<Steps>
  <Step>

    ### Install tools and dependencies
    ```bash
    mise trust && mise install && mise run setup
    ```

  </Step>
  <Step>

    ### Start the dev servers
    ```bash
    mise run dev
    ```
    Go API on `http://localhost:8060` (restarts on `.go` changes), SvelteKit on `http://localhost:9060` (proxies `/api`, `/images`, `/avatars` and `/healthz` to Go, so the browser sees one origin and the API's origin check still matches) - both by default; run `mise run ports` to see the numbers for this worktree, see [Work in a worktree](/howtos/work-in-a-worktree).

    Log in as `admin` / `admin1234` at `http://localhost:9060/login` (or the frontend port `mise run ports` gives this worktree); the task prints the pair as it starts. `REZEPTE_ADMIN_PASSWORD` has no default in the binary - an empty `users` table without it is `ErrAdminPasswordRequired` and the service refuses to start, see [Users and auth](/features/users-and-auth) - so `//service:dev` defaults it to the username with `1234` appended, like every bootstrapped account here ([Development credentials](/conventions/dev-credentials)); a value set in the environment still wins. That password creates the instance owner on the very first start and is read again only by `rezepte --reset-superadmin-password`.

    For an instance that already has recipes in it, `mise run demo` starts the built binary with the twelve samples on the demo port and keeps it up until Ctrl-C (`demo` / `demo1234`) - no dev server, no HMR, but nothing to fill in either ([Demo mode](/features/demo-mode)).

    Uploads land in `$REZEPTE_DATA_DIR/images/<recipeId>/` (default `./data/images/` relative to where the binary runs, so under `service/` for `mise run dev`; git-ignored with the database, see [Architecture overview](/architecture/overview)); delete that directory together with `rezepte.db` when resetting local data.

  </Step>
  <Step>

    ### Run the docs
    ```bash
    mise run docs
    ```
    `mise run docs` starts the memory site on `http://localhost:4000` and the user docs on `http://localhost:4001/rezepte` by default - run `mise run ports` for this worktree's numbers, see [Work in a worktree](/howtos/work-in-a-worktree). The base path on the user docs is set unconditionally so dev matches production - see [Documentation sites](/architecture/docs). Both sites listen on `0.0.0.0` and both `next.config.mjs` files pass this machine's own IPv4 addresses as `allowedDevOrigins`, so a phone on the same network can open them: without that, Next answers the HTML but 403s every `/_next/*` chunk, and the page renders once and never hydrates.

  </Step>
  <Step>

    ### Build the production binary
    ```bash
    mise run build
    ```
    The frontend is built into `service/internal/web/dist` and embedded in `service/bin/rezepte`. To run it with sample data, use `mise run demo`; started by hand against an empty data directory, it needs `REZEPTE_ADMIN_PASSWORD` and refuses to start without it. `go run ./cmd/rezepte` without a build serves no frontend at all, because `dist` holds only `.gitkeep` in a fresh checkout.

  </Step>
  <Step>

    ### Run the gate
    ```bash
    mise run check
    ```

  </Step>
</Steps>

<Callout type="info">

  Use `mise tasks --all` to list every task, including package-local ones like `//service:test`.

</Callout>

## Known issues

<Callout type="warn">

  - An e2e run where every test that logs in fails with "That username or password is wrong." means a stale process on the port, not your change - see the trap under [Running a probe](/howtos/verify-ui#running-a-probe).

</Callout>
