---
title: Run the app locally
description: Dev servers, builds and the check gate
---

<Steps>
  <Step>

    ### Install tools and dependencies
    ```bash
    mise trust && mise install && mise run setup
    ```

  </Step>
  <Step>

    ### Start the dev servers
    ```bash
    REZEPTE_ADMIN_PASSWORD=change-me mise run dev
    ```
    Go API on `http://localhost:8060` (restarts on `.go` changes), SvelteKit on `http://localhost:9060` (proxies `/api` and `/images` to Go) - both by default; run `mise run ports` to see the numbers for this worktree, see [Work in a worktree](/howtos/work-in-a-worktree).

    The password is only used on the very first start to create the `admin` user. Log in at `http://localhost:9060/login` (or the frontend port `mise run ports` gives this worktree).

    Uploads land in `$REZEPTE_DATA_DIR/images/<recipeId>/` (default `./data/images/`, git-ignored with the database, see [Architecture overview](/architecture/overview)); delete that directory together with `rezepte.db` when resetting local data.

  </Step>
  <Step>

    ### Run the docs
    ```bash
    mise run docs
    ```
    `mise run docs` starts the memory site on `http://localhost:4000` and the user docs on `http://localhost:4001/rezepte` by default - run `mise run ports` for this worktree's numbers, see [Work in a worktree](/howtos/work-in-a-worktree). The base path on the user docs is set unconditionally so dev matches production - see [ADR 0015](/decisions/0015-publish-user-docs-to-github-pages).

  </Step>
  <Step>

    ### Try the app with sample data
    ```bash
    cd service && REZEPTE_DATA_DIR=$(mktemp -d) mise exec -- go run ./cmd/rezepte --demo
    ```
    (or the built binary, `./bin/rezepte --demo`, from a temporary `REZEPTE_DATA_DIR`). Seeds twelve sample recipes with placeholder photos and, with no `REZEPTE_ADMIN_PASSWORD` set, a `demo` / `demo1234` admin - log in at `http://localhost:8060`. Unlike `mise run dev` above, this runs the binary directly without setting `REZEPTE_ADDR`, so it always binds `:8060` regardless of this worktree's offset. See [ADR 0013](/decisions/0013-demo-mode-and-docs-pipeline).

  </Step>
  <Step>

    ### Build the production binary
    ```bash
    mise run build
    ./service/bin/rezepte
    ```
    The frontend is built into `service/internal/web/dist` and embedded.

  </Step>
  <Step>

    ### Run the gate
    ```bash
    mise run check
    ```

  </Step>
</Steps>

<Callout type="info">

  Use `mise tasks --all` to list every task, including package-local ones like `//service:test`.

</Callout>

## Known issues

<Callout type="warn">

  - Docker Desktop's credential helper (`docker-credential-desktop`) can hang on image pulls on macOS. Use a throwaway `DOCKER_CONFIG` directory without `credsStore` for local builds.
  - If `bunx playwright install chromium` times out downloading, run it once from a normal terminal. `mise run setup` is idempotent and will pick up the cached browser on the next run.
  - Chromium does not start on the current development machine, so `mise run e2e` cannot run there; the Phase 4 e2e tests are type-checked by `mise run check` and executed in CI only.
  - `mise run //docs/user:screenshots` needs a Chromium that starts; on this machine the PNGs are not generated - pages show placeholder frames instead (see [ADR 0013](/decisions/0013-demo-mode-and-docs-pipeline)).

</Callout>
