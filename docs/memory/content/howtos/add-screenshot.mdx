title: Add a screenshot
description: A new <Screenshot> name, its spec and its four PNGs
---

<Steps>
  <Step>

    ### Add a test to the matching spec
    Pick the `docs/user/screenshots/*.spec.ts` file for the area of the app (`auth`, `overview`, `recipes`, `cooking`, `settings`) and add a `test('<name>', …)` using the shared helpers:

    ```ts
    import { prepare, shot } from './helpers';

    test('<name>', async ({ page }, testInfo) => {
      await prepare(page, testInfo, { login: true });
      await page.goto('/some/route');
      // wait for whatever makes the page ready, then:
      await shot(page, '<name>');
    });
    ```

    `prepare` fixes the clock, sets the theme matching the project (light/dark) and optionally logs in as the demo admin (`demo` / `demo1234`). Use `ensureUser(page, username, password, role)` first when the shot needs a fixture the demo seed does not provide (the `settings` spec's `users` test creates a second account this way, so all four projects see it without seeding it four times).

  </Step>
  <Step>

    ### Reference it from the page
    ```mdx
    <Screenshot name="<name>" caption="…" />
    ```
    Add `mobile` for the phone-frame variant instead of the desktop one: `<Screenshot name="<name>" caption="…" mobile />`. The name must be `a-z0-9-` - `docs/user/scripts/screenshots-audit.ts` rejects anything else.

  </Step>
  <Step>

    ### Audit, then regenerate when you can
    ```bash
    mise run //docs/user:screenshots:audit
    ```
    Fails if the name has no matching `test()` or an invalid character; warns about missing or unused PNGs. Where a Chromium starts, follow with `mise run //docs/user:screenshots` to render the four PNGs the name now needs (`<name>-desktop-light.png`, `<name>-desktop-dark.png`, `<name>-mobile-light.png`, `<name>-mobile-dark.png`) into `docs/user/public/screenshots/`. Where it does not, `<Screenshot>` shows a placeholder frame until someone with a working browser runs it - see [ADR 0013](/decisions/0013-demo-mode-and-docs-pipeline).

  </Step>
</Steps>

## SCREENSHOT_BASE_URL

`docs/user/playwright.config.ts` (the screenshot specs' `baseURL`) and `docs/user/scripts/fetch-openapi.ts` both read `SCREENSHOT_BASE_URL`, defaulting to `http://localhost:8070` (offset 0; `mise run ports` gives this worktree's number) - the port `docs/user/scripts/with-demo.sh` starts `rezepte --demo` on. Override it only when you are pointing the specs or the OpenAPI fetch at an instance you started yourself (a different port, a remote host) instead of letting `with-demo.sh` manage one; the mise tasks (`screenshots`, `screenshots:check`, `openapi`) already wrap the specs in `with-demo.sh` and need no override for normal use.

Note: `first-login` (`getting-started/first-login.mdx`) and `settings` (`guide/settings.mdx`) both navigate to `/settings` and wait for the same "Passwort ändern" heading, so their four PNGs are nearly identical pairs. A future pass should either make the two pages show something different or drop one of the two `<Screenshot>` uses.
