---
title: Add a screenshot
description: A new <Screenshot> name, its spec and its four PNGs
---

<Steps>
  <Step>

    ### Add a test to the matching spec
    Pick the `docs/user/screenshots/*.spec.ts` file for the area of the app (`auth`, `overview`, `recipes`, `cooking`, `settings`) and add a `test('<name>', …)` using the shared helpers:

    ```ts
    import { prepare, shot } from './helpers';

    test('<name>', async ({ page }, testInfo) => {
      await prepare(page, testInfo, { login: true });
      await page.goto('/some/route');
      // wait for whatever makes the page ready, then:
      await shot(page, '<name>');
    });
    ```

    `prepare` fixes the clock, sets the theme matching the project (light/dark) and optionally logs in as the demo admin (`demo` / `demo1234`). Use `ensureUser(page, username, role)` first when the shot needs a fixture the demo seed does not provide - it derives the password from the username ([Development credentials](/conventions/dev-credentials)) (the `settings` spec's `users` test creates a second account this way, so all four projects see it without seeding it four times). Write every locator against the English strings in `frontend/messages/en.json`: this suite runs against the demo instance's default locale, English, the same language as `frontend/e2e` - see [Languages](/features/languages).

  </Step>
  <Step>

    ### Reference it from the page
    ```mdx
    <Screenshot name="<name>" caption="…" />
    ```
    Add `mobile` for the phone-frame variant instead of the desktop one: `<Screenshot name="<name>" caption="…" mobile />`. The name must be `a-z0-9-` - `docs/user/scripts/screenshots-audit.ts` rejects anything else.

  </Step>
  <Step>

    ### Audit, then regenerate when you can
    ```bash
    mise run //docs/user:screenshots:audit
    ```
    Fails if the name has no matching `test()` or an invalid character; warns about missing or unused PNGs. Where a Chromium starts, follow with `mise run //docs/user:screenshots` to render the four PNGs the name now needs (`<name>-desktop-light.png`, `<name>-desktop-dark.png`, `<name>-mobile-light.png`, `<name>-mobile-dark.png`) into `docs/user/public/screenshots/`. Where it does not, `<Screenshot>` shows a placeholder frame until someone with a working browser runs it - see [Documentation sites](/architecture/docs).

  </Step>
</Steps>

## SCREENSHOT_BASE_URL

`docs/user/playwright.config.ts` (the screenshot specs' `baseURL`) and `docs/user/scripts/fetch-openapi.ts` both read `SCREENSHOT_BASE_URL`, defaulting to `http://localhost:8070` (offset 0; `mise run ports` gives this worktree's number) - the port `mise run demo` starts `rezepte --demo` on. Override it only when you are pointing the specs or the OpenAPI fetch at an instance you started yourself (a different port, a remote host) instead of letting `//:demo` manage one; the mise tasks (`screenshots`, `screenshots:check`, `openapi`) already wrap the specs in `mise run demo --` and need no override for normal use.

A new shot of a page that already has one earns its place only by showing something the existing one does not. Where the demo seed cannot produce a state - `first-login` shows the empty overview of a fresh instance - the test answers the page's own list calls with `page.route` and leaves the session and everything else to the instance.
