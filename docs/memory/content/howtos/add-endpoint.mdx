title: Add an API endpoint
description: huma operations, security, errors

<Steps>
  <Step>

    ### Define input and output structs
    In the feature package's `handler.go`:
    ```go
    type getThingInput struct {
        ID string `path:"id" doc:"Thing id"`
    }
    type getThingOutput struct {
        Body ThingResponse
    }
    ```
    Validation tags (`minLength`, `maxLength`, `enum`, `required`) are enforced by huma and end up in OpenAPI.

  </Step>
  <Step>

    ### Register the operation
    ```go
    huma.Register(api, huma.Operation{
        OperationID: "get-thing",
        Method:      http.MethodGet,
        Path:        "/api/v1/things/{id}",
        Summary:     "Get a thing",
        Tags:        []string{"things"}, // must also be declared in apiTags; see below
        Security:    auth.Protected(auth.ScopeRecipesRead), // decide whether an API token may
                                                      // reach this operation and with which
                                                      // scope; use auth.SessionSecurity instead
                                                      // when it must stay session-only (see
                                                      // below). The middleware is installed by
                                                      // httpserver.New before any operation can
                                                      // be registered.
        Errors:      []int{404},
    }, func(ctx context.Context, in *getThingInput) (*getThingOutput, error) {
        t, err := svc.ByID(ctx, in.ID)
        if errors.Is(err, thing.ErrNotFound) {
            return nil, huma.Error404NotFound("thing not found")
        }
        if err != nil {
            return nil, err
        }
        return &getThingOutput{Body: toResponse(t)}, nil
    })
    ```
    Scopes are a closed set declared in `service/internal/auth/token.go`; `auth.Protected` must be given one already in that list, since no token can ever satisfy a scope outside it.

    Get the current user with `auth.CurrentUser(ctx)`, which is already the `401` when there is none (`auth.UserFrom(ctx)` gives the bare `ok`).

  </Step>
  <Step>

    ### Declare the tag, if it is a new one
    An operation's `Tags` field names a tag; it does not declare it. Add a new name to `apiTags` in `service/internal/httpserver/api.go` with a one-line description, in the position the documentation should present it:

    ```go
    {Name: "things", Description: "The things an instance keeps."},
    ```

    Skip this step when the operation joins a tag that is already there. `TestEveryTagIsDeclared` fails on a tag used without a declaration - and on a declaration nothing uses, so remove one whose last operation is gone. Both renderings of the document need it: the Scalar page at `/api/v1/docs` titles its sections from it, and the user docs title, describe and order the reference folders by it ([Regenerate the API reference](/howtos/regenerate-api-reference)).

  </Step>
  <Step>

    ### Wire and test
    Call your package's `Register(srv.API(), …)` from `cmd/rezepte/main.go`. Test through `httpserver.New(...).Handler()` with `httptest` as in `internal/auth/handler_test.go`.

  </Step>
  <Step>

    ### Call it from the frontend
    Add the call and its types by hand to the resource's file in `frontend/src/lib/api/`; nothing generates them ([Architecture overview](/architecture/overview)).

  </Step>
  <Step>

    ### Regenerate the API reference
    The OpenAPI document changed, so run `mise run //docs/user:openapi` and commit `docs/user/public/openapi.json` and `docs/user/content/api/reference/`; CI regenerates them and fails on a difference ([Regenerate the API reference](/howtos/regenerate-api-reference)). The frontend calls the operation through a typed function in `frontend/src/lib/api/`, whose request and response types are written by hand there - no generator reads the OpenAPI document - and the feature's memory page names the new route.

  </Step>
</Steps>

Two exported types with the same name in different feature packages (two called `List`) give huma one schema name, and it panics while it generates the OpenAPI document. Name response types for what they hold (`OrderResult`, not `List`); `TestEveryFeatureRegisters` in `service/internal/httpserver/wiring_test.go` renders the whole document and fails on a clash. [HTTP API](/architecture/api) lists the `GET` route collision, nullable slices, `$ref` fields and `PUT` rules that already bite a new operation.

<Callout type="warn" title="Multipart uploads">

  For a file upload use `RawBody huma.MultipartFormFiles[T]` with a `huma.FormFile` field tagged `form:"file" contentType:"..." required:"true"`. huma validates the part's declared type (`422`). Set `Operation.MaxBodyBytes` (huma has no default for multipart, so without it the body is unlimited) and put `image.LimitUpload` (`internal/image/handler.go`) into the operation's `Middlewares`, which refuses an oversized declared length before anything is read. Serve a binary response from the operation too, as a `*huma.StreamResponse` - see below.

</Callout>

<Callout type="info">

  Unexpected errors returned from a handler become 500 with a generic body. The `httpserver` error hook logs the real error at Error level with the operation id, method and path, so wrap errors with context (`fmt.Errorf("...: %w", err)`) to make that log line useful.

</Callout>

<Callout type="info">

  Admin-only operations call `auth.RequireRole(ctx, user.RoleAdmin)` first (403 `admin role required`); it asks `Role.IsAdmin`, so the instance owner counts as an admin, and `RequireRole(ctx, user.RoleSuperadmin)` is the owner-only form (403 `superadmin role required`). `Security` is a separate, earlier layer: `auth.Protected(scopes...)` decides whether a token may reach the operation at all before `RequireRole` ever runs, so a token needs both the matching scope and an admin owner to pass an admin-only operation.

  `RequireRole` hands back the caller, and that is what the third layer needs: an operation acting on another user account passes the caller into the service, which applies the rank rules in `service/internal/user/permission.go` - an admin manages plain members, anything touching an admin or the instance owner belongs to the owner (see [Users and authentication](/features/users-and-auth)). Scope answers "may this credential reach the operation", role answers "may this caller use it at all", rank answers "may this caller do it to that target".

  An operation that changes a recipe or anything under it (its images included) calls `recipe.GuardEdit` inside its transaction, which returns `ErrNotFound` or `ErrEditForbidden` for this actor ([Editing rights](/features/editing-rights)).

</Callout>

## Non-JSON responses

A huma operation frames its response as JSON unless it returns a `*huma.StreamResponse`, which is how a byte stream (an image, a download) stays an operation and so stays in the document: its `Body` gets the `huma.Context`, and `humago.Unwrap(ctx)` yields the `*http.Request` and `http.ResponseWriter` for `http.ServeContent` or a foreign handler. Return a `huma.Error…` before the stream for a failure, since the stream itself can no longer change the status. A stream has no schema, so declare the `200` in `Responses` by hand; for a JPEG, return `image.JPEG(f, cacheControl)` and use `image.JPEGResponses` (`internal/image/file.go`). Security, tags and path parameters work as for any operation, even for a path outside `/api/v1`. Register every API route as a huma operation; the server has no plain-route escape hatch, and a route outside huma would be missing from the document ([HTTP API](/architecture/api)).

A change that adds a field to a recipe or a step touches more than the operation; follow [Adding a field to a recipe or a step](/features/recipes#adding-a-field-to-a-recipe-or-a-step).
