---
title: Add a route
description: Page, +page.ts load, guard, messages
---

<Steps>
  <Step>

    ### Create the route file(s)
    `src/routes/<path>/+page.svelte`. Add a `+page.ts` only when the page needs a typed `load` - for example to parse the URL into initial state before the component reads `data` (the overview route's `+page.ts` just calls `parseListQuery(url)`; see `src/lib/recipe/query.ts`).

  </Step>
  <Step>

    ### Fetch client-side
    `ssr = false` is set once, in the root `+layout.ts`, for the whole app - there is no server render to hydrate. From there, either the component fetches in `onMount` (so it can render a skeleton while the request is in flight, as the overview page does), or `load` awaits the fetch directly when there is nothing meaningful to show before the data arrives (as `recipes/[slug]/+page.ts` awaits `loadRecipeBySlug` from `src/lib/recipe/load.ts`). Pick whichever fits the page; do not fetch in both places.

  </Step>
  <Step>

    ### Auth guard
    Every route is already guarded by the root `+layout.ts`: without a session it calls SvelteKit's `redirect()` to `/login?next=<path>`. Do not add a per-route guard. A page that must open without a session (sign-in, password reset, email confirmation) goes into `authPages` in `src/lib/auth.svelte.ts`; public shares under `/s/` are exempted in the layout itself, before it asks for a session.
    A route whose own `load` can't find its resource throws `error(404, m.not_found())` (see `loadRecipeBySlug` in `src/lib/recipe/load.ts`) - a 404 is not a redirect.
    An admin-only page adds a `+page.ts` whose `load` does `const { user } = await parent();` and `redirect(302, '/settings')`s when `!isAdminRole(user?.role)`; the API still enforces the role.

  </Step>
  <Step>

    ### Wire up navigation
    Link to the new route with `resolve('/path')` from `$app/paths`, never a raw string `href` - `resolve` is checked against the route tree at compile time. Add the link wherever a user should reach the page (`TopBar`, `BottomNav`, a card, ...).

  </Step>
  <Step>

    ### Messages and title
    Every string on the page goes through Paraglide - see [Add a translation](/howtos/add-translation). The page renders its own `<svelte:head><title>` ([Svelte conventions](/conventions/svelte)).

  </Step>
  <Step>

    ### Validate and commit
    svelte-autofixer on every changed `.svelte` file, then `mise run //frontend:fmt` and `mise run //frontend:check`. A page users reach gets an e2e spec ([Verify UI](/howtos/verify-ui)), and a page the user docs show gets its screenshots ([Keep the user docs in step with the UI](/howtos/update-user-docs)).

  </Step>
</Steps>

<Callout type="info">

  `resolve()` cannot type-check against a route that does not exist yet. When a change is split across tasks and a link's target route ships later, use a plain `<a>` with `<!-- eslint-disable svelte/no-navigation-without-resolve -->` around it as a stopgap, with a `TODO(<task>)` comment, and switch it to `resolve()` in the task that adds the route.

</Callout>

<Callout type="info">

  A route that must fill the whole screen (cooking mode) is not a layout of its own: add its route id to the `isFullscreenRoute` check in `src/routes/+layout.svelte`, which then renders the page without `AppShell` and the command palette. See [Cooking](/features/cooking).

</Callout>
