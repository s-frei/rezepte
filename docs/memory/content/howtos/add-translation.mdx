<Steps>
  <Step>

    ### Add the key
    `frontend/messages/en.json` and `frontend/messages/de.json` are flat JSON objects (inlang message format), each holding the same set of keys. Add a new key to `en.json` first, and to `de.json` in the same commit - the parity gate in `mise run check` (`frontend/scripts/message-parity.ts`) fails the build if the two catalogues' key sets ever differ. Name keys `<area>_<name>` (`overview_search_placeholder`, `detail_delete_confirm_title`, ...), grouped under the existing blank-line-separated sections by area. Interpolate with `{param}` placeholders:
    ```json
    "overview_no_results_text": "No recipes found for \"{query}\"."
    ```

  </Step>
  <Step>

    ### Use it
    ```ts
    import { m } from '$lib/paraglide/messages';

    m.overview_load_more();
    m.overview_no_results_text({ query });
    ```
    Never write a UI string directly in a component, in either language - see the hard rule in `AGENTS.md`.

  </Step>
  <Step>

    ### Regenerate
    Nothing to run by hand: the Vite plugin (`paraglideVitePlugin`, configured in `frontend/vite.config.ts`) regenerates `src/lib/paraglide/*` whenever the dev server starts or the app builds. If a brand-new key doesn't type-check yet, restart the dev server.

  </Step>
</Steps>

<Callout type="info">

  Adding a whole language rather than a key is [Add a language](/howtos/add-language): three lists, a catalogue and a set of sample recipes, with a test that names whichever one is still missing.

</Callout>
