title: Testing

---

<Tabs items={['Go', 'Frontend']}>
  <Tab value="Go">

    - Standard `testing` package, table tests with `t.Run`, no assertion libraries, no mocking frameworks.
    - Database tests run against a real migrated database, never a mock or a hand-built schema: take one from `dbtest.Open(t)` in `service/internal/db/dbtest/`. [Data model](/architecture/data-model) owns what it opens.
    - Handler tests build the real server - `httpserver.New` with `auth.Middleware`, the package's `Register` and a `dbtest.Open(t)` database - and drive `srv.Handler()` with `net/http/httptest` requests, so every request passes the same middleware, origin check and validation as in production. Not `humatest`, which would skip the middleware.
    - Test names describe behavior: `TestCreateRecipeRejectsEmptyTitle`.
    - A test that costs seconds calls `t.Parallel()`, as the `demo.Seed` tests in `service/internal/demo/` do: every seed renders all embedded photos, and run one after another they would make that package the longest step of `check`. A test that swaps package-level state, such as `photos` in that package, stays serial; Go finishes the serial tests before it starts the parallel ones.
    - `//service:test` runs `go test -trimpath`: without it the checkout's directory is part of the test cache key, and a new worktree reruns every package instead of reusing the main checkout's results.
    - `mise run check` runs the module without `-race`. Run `go test -race` on the packages with real concurrency you touched - `internal/oidc`, `internal/auth`, `internal/user`, `internal/userapi` - never on `./...`: argon2 and the demo's image rendering crawl under the race detector and turn minutes into a quarter of an hour.

  </Tab>
  <Tab value="Frontend">

    - Vitest for pure logic (`src/lib/**/*.test.ts`): API client, scaling, formatting.
    - Playwright end-to-end tests in `frontend/e2e/` against the built binary (`mise run e2e`), desktop and mobile projects. One test per user-facing flow.
    - Users a test bootstraps take their password from their username, through `devPassword` in `frontend/e2e/helpers.ts` ([Development credentials](/conventions/dev-credentials)); Go unit tests keep their own fixture passwords.
    - `bun run lint` keeps Prettier's and ESLint's caches in the frontend's node_modules, so a repeated local lint takes a second instead of ESLint's twenty (its typed `projectService` setup is what `svelte/no-navigation-without-resolve` needs). A cached result can miss a type change in another file; CI starts without a cache, so it catches that.
    - These caches, like the docs sites' `.next/cache`, key their entries by absolute path, so a new worktree starts cold and a copy from the main checkout never hits; a seeded `.next/cache` even builds slower than none.
    - `svelte-check` and ESLint are part of the gate; no component tests. `svelte-check` type-checks the Playwright specs and `playwright.config.ts` too: the kit's `typescript.config` hook in `frontend/vite.config.ts` adds them to the generated tsconfig's `include`.

  </Tab>
</Tabs>

`mise run check` runs every package gate. CI runs the same gates, each on a runner of its own ([GitHub Actions](/conventions/github-actions)), and more besides, so a green `check` locally is not the whole of the CI job ([Toolchain](/architecture/toolchain)).

<Callout type="warn" title="UI changes and the user docs">

  A UI or API change is not done until the affected page under `docs/user/content/` is updated and, where Chromium runs, the screenshots are regenerated with `mise run //docs/user:screenshots` and committed with the feature; the API reference is regenerated with `mise run //docs/user:openapi` (checked in CI). See [Keep the user docs in step with the UI](/howtos/update-user-docs).

</Callout>
