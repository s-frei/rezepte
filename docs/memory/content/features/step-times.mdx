---
title: Step times
description: A duration in a step's text, authored in the editor, stored as seconds, highlighted on the detail page and in cook mode
---

A duration in a preparation step - "90 Minuten", "20-25 minutes", "1 Std. 30 Min." - can be marked. The detail page and cook mode then show it with a clock glyph and a dotted underline, so a cook sees where a step waits, and the stored seconds are what a later cook-mode timer will run on. `service/internal/recipe/times.go` owns validation and storage; `frontend/src/lib/recipe/times.ts` and `step-times.ts` own detection and the editor's bookkeeping.

## How it works

**The wire format sits beside `references`.** `Step.Times` is `[]StepTime`, on the wire `times: [{phrase, seconds, maxSeconds?}]`. `phrase` is the text as it stands in the step, the anchor, never an index. `seconds` is 1 to 604800 (one week); `maxSeconds` is present only for a range and lies above `seconds` and at most 604800. The same shape travels everywhere a step does: REST, MCP, zip export and import, public shares. Over REST `times` is `required:"false"`, so an old client or archive without it stays valid; over MCP `requireStepLists` in `service/internal/mcpserver/schema.go` requires it, as it does `references`.

**Validation runs before the transaction, through `resolveRefs`.** `validateTimes` is pure. For every time it requires at least one number rune in the phrase (`unicode.IsNumber`, so "½ Stunde" counts), each phrase at most once per step, occurring in the text on whole-word boundaries (`containsWord`, the check references use), and a range running upward. `containsWord` treats letters and `unicode.IsNumber` runes as word characters, the `\p{L}\p{N}` class the frontend's `wordPattern` uses, so a phrase "1" in "1½ Stunden" is refused on both sides. The other limits are huma schema tags, checked before `validateTimes` runs on REST, MCP (whose tool schema comes from the same registry) and zip import (`transfer.InputValidator`): `minLength:"1"` and `maxLength:"60"` on `StepTime.Phrase`, `minimum:"1"` and `maximum:"604800"` on both second fields, and `maxItems:"20"` on `Step.Times`. A failure is a `RefError` whose `List` is `"times"` (references use `"references"`), mapped to a `422` at `body.steps[i].times[j].<field>`.

**Storage is one table.** Migration `0013_step_times.sql` creates `step_times`, keyed by `(step_id, phrase)` and cascading with `DeleteStepsByRecipe`, which every save runs. `writeChildren` inserts inside the save's transaction and reading assembles `Step.Times` beside `Step.References`. See [Data model](/architecture/data-model).

**Rendering looks stored times up and detects nothing.** `segmentStep` splits a step's text at the first occurrence of each stored reference word and phrase; if two overlap the earlier one wins. `StepText.svelte` draws a time as a clock icon and the text, in `text-time-foreground`, semibold, dotted underline, sized in em so cook mode's type sizes scale it, and puts a `data-time` attribute on the span. The span is an `inline-block max-w-full`: a time moves to the next line whole, and only one wider than the line wraps inside its own box. Browsers break after an inline icon whatever follows it, so the box is what keeps the clock with its number, and one text node keeps the dotted underline in one rhythm. Each number is tied to the word after it with a no-break space, so "20 bis 25 Minuten" never wraps between "25" and "Minuten", and `hyphens-none` keeps Safari, which ignores cook mode's twelve-character limit, from splitting "Mi-nuten". There is no ARIA: the visible text is the accessible text. The color is the `time-foreground` token in [Design system](/architecture/design-system). Cook mode shows nothing beyond that.

**The detector runs only in the editor.** `suggestTimes` in `times.ts` finds a number plus a unit (`90 Minuten`, `2,5 Stunden`, `1.5 hours`, `½ Stunde`), a range (`20-25 min`, `20 bis 25 Minuten`, `20 to 25 minutes`) and a compound (`1 Std. 30 Min.`, `1 hour 30 minutes`), and leaves `2 Eier`, `180 °C`, `3 EL` and a bare number alone. A decimal separator counts only between digits, so "5, 10 Minuten" is two numbers; ½, ¼ and ¾ may follow a number or stand alone. A unit is not followed by a letter or digit, and the number has none before it. A recipe has no language, so `catalogUnits` reads the unit words of every locale at once from the message catalogs: `time_units_seconds`, `time_units_minutes`, `time_units_hours`, `time_words_range` and `time_words_and`, each a `|`-separated list, merged across `locales` through Paraglide. These keys are data for the detector, not UI copy, and `message-parity.ts` forces a new language to provide them. There is no single-letter "s" or "m". Matching is case-insensitive, an earlier start wins and then the longer match, and a result the service would refuse (a phrase over 60 characters, seconds out of range) is never proposed. A match is proposed only where `wordPattern` anchors its phrase, the first whole-word occurrence: a repeated "20 Minuten" or a "30 Minuten" that first appears inside "1 Stunde 30 Minuten" yields nothing, so every proposal's phrase is unique and the editor's keyed lists never see a duplicate. `times.test.ts` holds the sample recipes (`service/internal/recipe/testdata/recipes.{de,en}.json`) to the detector: every stored time is what it proposes for that step, and it proposes nothing else.

**The editor reuses the reference machinery.** `step-times.ts` holds the bookkeeping: `presentTimes` is what the text still carries, `pendingTimes` the detector's proposals that are neither stored nor dismissed and overlap no linked ingredient word and no stored time - except a stored time they wholly contain: a stored "20 Minuten" the author has since written out to "1 Stunde 20 Minuten" lets the whole be proposed, and `addTime` replaces every stored time whose phrase stands within the one it adds. `isMarked` (overlapping a stored time or a linked word) and `removeTime` complete it. `StepField.svelte` draws a stored time solid and a proposal dotted, and putting the caret inside one opens the card (a proposal before a stored time it contains, through `caretTimePhrases`, since the proposal is the actionable one) with "Accept" / "Dismiss" for a proposal and "Remove" for a stored time. "Mark as time" beside "Link word" takes the selection and opens a small popover with the number read from it and a choice of seconds, minutes or hours; it is refused for a selection with no number, one over 60 characters or one overlapping an existing mark; a number out of range for the chosen unit leaves the popover's "Set" disabled, since another unit may fit. The popover is a Bits UI `Popover` with no trigger, anchored at the selection through `customAnchor`; focus starts on the checked unit, Escape and "Set" hand it back to the step, and a press or Tab outside closes it and leaves focus where it went. It stays in place, without a portal or focus trap, so Tab walks on through the page. Bits UI also reports a close when a reopen replaces the last focus scope, so the hand-back only fires while the popover is closed. The step-times e2e runs in WebKit too, because Safari focuses no button on click. "Link word" in turn refuses a word inside a stored or proposed time. The reason shows under the buttons until the selection changes - the same line for "Link word"'s refusals. A `role="status"` line says it to a screen reader, so the visible copy is `aria-hidden` and nothing is read twice. `StepLinks.svelte` counts times apart from links ("2 times") and lists each stored and pending time in the folded list - phrase, formatted duration, remove button - which is also the keyboard and screen-reader path. `formatDuration` builds on `formatMinutes` and its `duration_*` catalog keys plus `duration_seconds`: "1 hr 30 min", "5 min 30 sec", and a range shares a lone unit ("20–25 min") or spells out both ends ("45 min–1 hr 30 min"). Saving accepts open time suggestions together with reference suggestions, and "Saving accepts N suggestions" counts both. In the form model `FormStep.times` is carried by `fromRecipe` and `toInput`; a stored time whose phrase an edit removed stays on the step out of sight and `toInput` drops it, the rule `presentReferences` applies, so undo brings it back.

## Why it is this way

A time is authored data, like a reference: the detail page and cook mode show only what somebody confirmed, so a wrong guess never reaches a cook. The detector may therefore be eager, because a proposal costs one click, and it lives only where a person reviews it.

Recipes have no language, so the detector cannot pick one unit list; it takes every locale's words. A German recipe with an English "min" still matches.

There is no control character like `@` for ingredients: there is nothing to pick from, since the time is what the author types anyway.

Only text with a number counts. "über Nacht" and "einige Minuten" have no duration a timer could run on, and a marked time that cannot be counted would mislead.

The author can always refuse: dismiss a proposal, remove a stored time from the card or the list.

## Rejected

- **Detection at render time.** The detail page would then show guesses nobody reviewed, and cook mode would carry the detector, its catalogs and its false positives.
- **A control character that starts a time.** Nothing is chosen from a list, so the character would only add a keystroke before text the author writes anyway.
- **Vague durations with an author-set duration** ("über Nacht" as 8 hours). It turns prose into a promise the author never typed, and the phrase would have no number to anchor the validation on.
- **Storing unit text or ISO 8601.** The unit words are language; seconds are what a timer needs, and a string would have to be parsed back by every reader.
- **Positional anchors.** Rejected for the same reason as for references: steps are rewritten wholesale on every save.

## Limits

- Existing recipes gain times only when somebody saves them in the editor; nothing backfills.
- A language whose catalog has no unit words gets no suggestions, only "Mark as time".
- A final dot belongs to the phrase only where the sentence goes on in lower case (`ownDot` in `times.ts`): "10 Min. backen" keeps it, "bake 10 min." does not. German capitalizes nouns, so "10 Min. Teig ruhen lassen" is proposed as "10 Min" without its dot - harmless, since the dot is the one character that would only decorate the mark.
- A phrase is marked at most once per step, and the first occurrence is the one that is drawn.
- "Mark as time" reads only the first number of a word range or compound: "20 bis 25 Minuten" becomes 20 minutes, "1 Std. 30 Min." becomes 1 of the chosen unit. The popover's preview shows the result before it is set.
- There is no day unit: a duration in days ("3 Tage marinieren") is not a time, and "Mark as time" offers at most hours.
- The timer is not built yet; `seconds` and `maxSeconds` are stored for it.
