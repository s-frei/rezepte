---
title: Recipe import
description: A link to a recipe page or pasted recipe text becomes an unsaved draft in the new-recipe editor; every member
---

Every member can turn a recipe on a website, or recipe text copied out of a mail, a chat or a note, into a draft in the new-recipe editor, check it and save it. Nothing is stored until they save, and saving is the ordinary `POST /api/v1/recipes`. `service/internal/recipeimport` fetches and reads; `frontend/src/lib/components/import/` holds the dialog; [HTTP API](/architecture/api) owns the two endpoints. The zip import between instances is a different feature, for admins: [Import and export](/features/import-export).

## How it works

**Entry points.** The top bar, the empty overview, the command palette and the phone's New sheet (`frontend/src/lib/components/shell/NewSheet.svelte`) all open the import dialog, for every role, through one flag, `importDialog` in `frontend/src/lib/import.svelte.ts`. `ImportDialog.svelte` is mounted once in the root layout and shows `ImportForm.svelte` in a `BaseDialog` on a wide screen and in a `BottomSheet` below `md`.

**Share → Rezepte.** The manifest's `share_target` and its "Import" shortcut point at `/import` (`frontend/src/routes/import/+page.svelte`). The page reads `title`, `text` and `url` through `sharedInput`: an http(s) `url` wins, else the first link inside `text`, else the `text` itself; the `title` is never a recipe. It replaces its own history entry with the overview (Back and a reload do not import again), and only then calls `openImport(value)`: the dialog opens over the overview with the value in the field and waits for Import (`importDialog.prefill`, taken in an `$effect` in `ImportForm`, so a share into an already open dialog replaces its field and cancels a read in flight). It does not read at once: a dialog that leaps to the editor before the member has looked at the link feels wrong. Opening it before the overview had settled let a fast draft lose to the overview's own `replaceState`, so the overview's `syncUrl` also stands down while another navigation runs. Signed out, the root layout sends `/import?...` through `/login?next=` and the share resumes after sign-in.

**Launches into an open window.** With `launch_handler: focus-existing` the installed app does not reload for a second share; `listenForLaunches` (`frontend/src/lib/launch.ts`, started from the root layout) gets the target through `launchQueue` and `goto`s it unless it is the first launch and matches the page that loaded (`launchFilter` forgets that href after one look, so sharing the same link again later navigates). That navigation passes through `RecipeForm`'s leave guard, so an editor with unsaved changes asks first; the guard sees the target is `/import` and words its `ConfirmDialog` for the share ("Discard changes and import the link?", with "Keep editing" as its `cancelLabel`), and "Keep editing" drops the share. The e2e stubs `window.launchQueue` with `Object.defineProperty`, since Chromium's own is read-only.

**The dialog.** One field takes a link or text. `detectInput` in `frontend/src/lib/recipe/import-input.ts` decides which: a single token that `URL` parses with `http:` or `https:` is a link, anything else is text, and the line under the field says which. A short example recipe, the message `import_example`, shows how text should look - in the empty field's placeholder, and once the field holds text in a disclosure. Each language writes it with its own import table's headings, and `TestEveryAppLanguageExampleImportsCleanly` reads every catalog's example with that table and fails unless it imports with a title, two ingredients that need no check and a step. The answers it can get:

| Reason (`422`, `errors[0].message`) | The dialog |
|---|---|
| `no-recipe` | "We found no recipe on …"; the field empties for the page's text and the link stays as "Source:", becoming the draft's `sourceUrl` when the text is imported |
| `unreachable` | "We couldn't open this page."; the field keeps the link |
| `no-recipe-in-text` | "We couldn't find a recipe in this text." |
| a `duplicate` in the draft | "This recipe is already here: … · by …" with Back (to the field, text kept), View and Import anyway (disabled while the photo loads) |

Admins also see a row linking to the zip import at `/settings/transfer#import`.

**The hand-over.** The dialog redeems the draft's photo link while it still shows "Reading …", puts `{draft, photo, photoFailed}` into `frontend/src/lib/recipe/draft.ts` and navigates to `/recipes/new`, which takes it out once (`takeDraft`) and prefills the editor. A reload of `/recipes/new` finds nothing and shows an empty editor.

- From `/recipes/new` itself it navigates too: the page stays, takes the draft in `afterNavigate` and restarts its editor (`{#key}`).
- An editor with unsaved changes, there or on any other recipe, holds the navigation with its "Discard changes?" dialog while the draft waits. "Discard" carries on into the import; closing that dialog any other way keeps the typed recipe and drops the draft (`RecipeForm` calls `takeDraft` and throws it away), so it never surfaces in a later "New recipe".
- Closing the import dialog while it reads aborts both requests the moment `importDialog.open` turns false, not when the form unmounts after the fade-out, and a draft that still arrives is not handed over: no draft, no navigation, no error toast.
- A new link clears the "no recipe" fallback source, so a later text never inherits an older page, and a fallback link over 500 characters (the service's limit for a source) is not kept.
- The photo is a queued file, uploaded after the create like any photo picked before the first save. A failed photo and a truncated draft each raise one toast.

**Editor-only state.** An ingredient the parser was unsure about carries `source`, its original line, on `FormIngredient` (`applyReview` in `frontend/src/lib/recipe/form.ts` sets it from `review`); its row asks for a check and shows the original, and editing or dismissing the row clears it. `toInput` drops it, so it is never stored and never blocks saving. Keywords that would be new tags are suggestions under the tag field (`TagSuggestions.svelte`, styled with the step links through `frontend/src/lib/components/editor/link-list.ts`); whatever is left open is not saved.

**The service.** `recipeimport.Service` reads a link with `FromURL` (decoding the page to UTF-8 by its declared charset with `golang.org/x/net/html/charset`, so a Latin-1 page keeps its umlauts) and text with `FromText`; both end in `Build` (`draft.go`), which reads every ingredient line with the language table the reader chose, sets keywords that match an existing tag case-insensitively as tags in the collection's spelling and returns the rest as `suggestedTags`; a keyword equal to an author's name (`Page.Authors`, every author, case-insensitive) is neither, because sites such as BBC Good Food list the author among the keywords.

- `fetch.go`: the `Fetcher`. Its `net.Dialer.Control` checks the actual address of every connection against `PublicOnly`, which refuses loopback, private, link-local (cloud metadata), CGNAT, multicast, unspecified and reserved addresses (`192.0.0.0/24`, `198.18.0.0/15`, `240.0.0.0/4`, site-local `fec0::/10`), and the IPv6 forms that carry an IPv4 address or tunnel to one: IPv4-mapped, IPv4-compatible (`::/96`), NAT64 (`64:ff9b::/96`, `64:ff9b:1::/48`), 6to4 (`2002::/16`) and Teredo (`2001::/32`). It runs per connection, after DNS and on every redirect, so neither a redirect nor DNS rebinding gets past it. The transport has no proxy, since a proxy would make the check see the proxy instead of the target. `http` and `https` only, at most 5 redirects, 10 s overall, 5 MiB per page and 10 MiB per photo. Every failure is the one `ErrUnreachable`, answered as `unreachable`; the log keeps the cause.
- `jsonld.go`: `ReadPage` collects every `application/ld+json` block with `golang.org/x/net/html`, repairs trailing commas and raw control characters before giving up on one, and takes the first `Recipe` from top-level lists, `@graph` or nested objects. Text loses its markup, entities and control characters; `br`, `p`, `li` and `div` separate words, inline tags such as `b` do not.
  - Fields: servings from `recipeYield`; minutes from ISO 8601 durations (tolerating `PT0D1H`; `totalTime` alone becomes cook minutes); steps from a string, strings, `HowToStep` and `HowToSection` (with two or more sections, each name prefixes its section's first step; a lone "Zubereitung" is dropped); tags from `keywords`, `recipeCategory` and `recipeCuisine`; the widest declared image, following `@id` references.
  - The source is the canonical URL (or `og:url`) when it is on the same site as the page, `www.` aside, else the page's own URL after redirects; the source name is `og:site_name`, else `publisher.name`.
  - A title that ends in the author's name (the `author`, followed through `@id` to its Person or Organization) loses it with the lower-case word or separator before it ("… von KochFan42"), on an exact match only; the description loses the sentences the table's `promo` patterns match ("Über 112 Bewertungen …").
- `text.go`: `ReadText` takes the first line as the title unless it is a heading (then the draft has none and the editor asks), the lines under an ingredients heading (`Zutaten`, `Ingredients`, …, from the table) as ingredients and the lines under a method heading (`Zubereitung`, `Method`, …) as steps, numbered or by paragraph; a heading ends the step before it. Without an ingredients heading, the first line that starts with a quantity opens the ingredient block, and the blank line after it or the first numbered line ("1. Mix.", which "1.5 l" is not) starts the steps; with one, such a line above it ("4 Portionen") stays in the description.
- `lang.go`, `lang_de.go`, `lang_en.go`: the language tables. Every word the readers look for - units, range words, plural markers ("Gurke(n)", "Zehe/n"), unit modifiers ("EL, gehäuft"), vague words, headings, step words, promo patterns - lives in one `language` value per language, registered in `languages`; the type's doc comments are the contract, and [Add an import language](/howtos/add-an-import-language) walks through it. `detectLanguage` picks the table: the Recipe's `inLanguage`, else a `WebPage` node's, else `<html lang>`, by primary subtag (`de-DE` → `de`); without one, or for pasted text, the table that recognizes most lines (a heading, a unit, a vague word, a plural marker), and on a tie all tables at once (`anyLanguage`). `Page.Language` names the table used. `TestEveryAppLanguageHasAnImportTable` fails when a locale in `service/internal/i18n/locales.json` has no table.
- `ingredient.go`: `parseLine` reads one line with one table: plural markers go, then the quantity (integers, decimals with `,` or `.`, thousands grouped by the table's `thousandsSeparators` ("1.000 g" in German), Unicode and slash fractions, mixed numbers, ranges as the lower bound with the range as note), a parenthesis right after it as note ("1 (14-ounce) can"), a unit from the table, a parenthesis right after the unit as note ("1 can (14 oz) tomatoes"), a unit modifier into the note, the name and a trailing note in the outermost balanced parentheses or after a comma. Notes lose leading commas, so WP Recipe Maker's "(, minced)" is "minced". `sure` is false when the line has a digit but no leading quantity, when it says something vague (as whole words), or when the name cannot be right in any language: empty, starting with punctuation, holding a `/` or with unbalanced parentheses. An unsure line without a quantity is kept whole as the name.
- `clamp.go`: every length and count is cut to the `recipe.Input` maxima, at a word boundary where one is near, and `truncated` says so. Suggestions over 40 characters or beyond 20 are dropped without it, since they are no recipe content. A draft is not run through the schema, because a draft may lack a title.

**Duplicates.** `recipe.Service.FindBySource` compares the entered URL, the URL after redirects and the canonical URL against the stored sources, both sides through `recipe.NormalizeSource` (lower-case scheme and host, no fragment, no `utm_*`); the newest match is `duplicate`. Text without a link never has one.

**Photo tokens.** The draft names its photo as `/api/v1/recipe-drafts/photo?src=…&token=…`. The token is made by `sign.Signer` (`service/internal/sign`) with the label `rezepte draft photo`, over the photo URL, for 2 minutes, under a 32-byte key drawn from `crypto/rand` at start and held in memory. The photo endpoint fetches only a `src` its token proves the service itself found, serves `image/jpeg`, `image/png` or `image/webp` with `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`, and answers `404` for anything else. The bytes are decoded only when the saved recipe uploads them, by `image.Service.Upload`.

**Access.** Both operations take any session or a token carrying `recipes:write`.

## Why it is this way

**A draft, not a recipe.** Saving at once would leave half-checked recipes behind whenever someone cancels; a draft costs nothing until the member agrees with it.

**One parser, in Go.** Pages are read on the server, which is the only place that can fetch them; reading pasted text there too keeps one ingredient parser instead of a Go and a TypeScript one that drift apart.

**Words in tables, rules in code.** A word list mixed into the parser grows by language until no one can say which word serves which; a table per language keeps the parser's rules (balanced parentheses, the safety net, the author in the title) the same for all of them, and lets someone who cooks in a language add it without reading the parser. Reading a page with its own table only also keeps the lists from colliding: English "to" is no German range word. The safety net exists because no table is complete: a line a missing word splits wrong comes out flagged, not confidently wrong.

**The guard sits in the dialer.** A check of the host name before the request misses redirects and DNS that answers differently the second time; the address a connection actually opens is the only one that matters. One error for every failure means the answer never tells whether something lives at a private address.

**A short-lived token, not a proxy.** A photo endpoint for any URL would make the service a downloader for every member; a signed `src` limits it to photos the service found itself, and two minutes covers a phone that pauses the tab while "Reading …" shows. A key drawn at start is enough for that: a restart costs at most a photo.

**Suggestions, not tags.** Sites put "Party" and "Deutschland" into their keywords; taking them all would fill the overview's tag filter whenever someone forgot to clean up.

## Rejected

- **Base64 photo in the draft JSON.** Bloats the response and the OpenAPI schema, one photo only.
- **An import resource with server-side state** (`POST /imports`, photos in a temp dir). State, expiry and a sweeper for a minute of life.
- **Parsing pasted text in the browser.** A second ingredient parser.
- **A Go scraping library.** The candidates are unmaintained, GPL or only find the JSON-LD blocks; normalizing into `recipe.Input` is the work, and none does it.
- **A "please check" flag in the database or a note in the recipe.** A migration for a state that matters until the first save, or polluted recipe data.
- **A switch to allow private addresses**, for e2e or for recipe sites on the home network. Set by mistake, it reopens the hole; the e2e suite stubs the draft answer for links instead.
- **A stored signing key for draft photos.** Link previews store theirs because their tokens live up to a day ([Link previews](/features/link-previews)); these live two minutes.

## Limits

- Pages that render their recipe with JavaScript and ship no JSON-LD, and pages behind bot protection or a paywall, work only through pasted text.
- One photo per import; nutrition, ratings, videos and the source's author are ignored.
- Pasted text fills no servings and no times - a "4 Portionen" line stays in the description - and every import lands in one ingredient group, so a line like "Für den Teig:" becomes an ingredient.
- Duplicates are found by source URL only, not by title.
- A reload of `/recipes/new` loses an imported draft.
- The import has tables for German and English, the app's two languages. A recipe in another language reads with both at once: its units are not recognized and stay in the name ("2 cuillères à soupe de farine" is 2 × "cuillères à soupe de farine", not flagged), and only lines the safety net catches are marked to check.
- The author's name comes off a title only on an exact match, but then also when it is part of the dish: "Pasta alla Norma" by an author named "Norma" becomes "Pasta".
- No import tool for [MCP](/features/mcp) and no bulk import of several links ([Roadmap](/roadmap)). iOS has no share target, and a browser without `launch_handler` reloads the window for a second share, where only `beforeunload` can warn about unsaved edits.
