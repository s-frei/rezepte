<Callout type="info">

  This section is the long-term memory for AI coding agents working on Rezepte. It is written for agents first, but stays readable for humans.

  It is not the end-user documentation. `docs/user/` is written for the people who cook from Rezepte and the people who host it for them, and nothing about developing Rezepte belongs there. The two sites are deployed separately ([Documentation sites](/architecture/docs)), so a sentence in the wrong one reaches the wrong audience.

</Callout>

## What Rezepte is

A self-hosted recipe manager for the people you cook with: a Go service serving a bundled SvelteKit SPA, SQLite for storage, sessions for login. The UI is English or German, per account; everything in the repository is American English ([Language](/conventions/language)). [Architecture overview](/architecture/overview) shows how `service/`, `frontend/` and `docs/` fit together.

## Where to look

Read the page for the thing you are about to change before changing it, and leave it saying the new thing when you are done ([Update the memory](/howtos/update-the-memory)). A user-visible capability with facts beyond its look has a page under `features/`, named after it ([what earns one](/howtos/update-the-memory#what-earns-a-page-under-features)); each one says how it works, why it is this way, which alternatives were refused and what it deliberately does not do.

## Repository map

Each folder is described where it is owned, so the list below names the page rather than repeating it:

- `service/`, `frontend/`, `docs/` – [Architecture overview](/architecture/overview), one line per package
- `mise/` and `mise.toml` – [Toolchain](/architecture/toolchain)
- `assets/` – the logo sources in [Design system](/architecture/design-system#logo), the README images in [Toolchain](/architecture/toolchain), the demo photos and pictures in [Demo mode](/features/demo-mode)
- `.github/` – [Releases](/architecture/releases) and [GitHub Actions](/conventions/github-actions)

`AGENTS.md` carries the hard rules every agent follows; [Update the memory](/howtos/update-the-memory#in-this-repository) says how it relates to `CLAUDE.md` and this site.

`CONTRIBUTING.md` and `SECURITY.md` are for strangers arriving on GitHub: where a bug, an idea, a question or a vulnerability goes, and what a pull request needs. They point into the user docs and into this memory rather than repeating either, so a rule changes in its own page and the two files only need touching when a channel changes.
