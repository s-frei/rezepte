---
title: "0018: Worktrees as the unit of feature work"
description: Feature work happens in a git worktree branched from develop, with a port offset per worktree so parallel stacks never collide
---

**Status:** accepted · 2026-09-19

## Context

Two agents working in the same checkout collide twice over. They collide in the working tree - one switches branches under the other - and they collide on ports, because every service in this repo binds a fixed number:

| Service | Port | Configured in |
|---|---|---|
| Go API | 8060 | `service/internal/config/config.go` (`REZEPTE_ADDR` default) |
| Vite dev server | 9060 | `frontend/vite.config.ts`, `strictPort: true` |
| Demo instance (screenshots, OpenAPI) | 8070 | `docs/user/scripts/with-demo.sh` |
| Docs memory | 4000 | `docs/memory/package.json` |
| Docs user | 4001 | `docs/user/package.json` |

The port collision is the nastier one: it does not look like a conflict. `with-demo.sh` already documented the symptom it produces, that a stranger holding `:8070` answers `/healthz` first and the pipeline silently screenshots *their* instance. The `e2e` task carried the same warning for `:8060`, where a foreign process turns every login into "Benutzername oder Passwort ist falsch" while the tests that do not log in still pass.

The worktree half of the problem has a second, smaller edge: the harness's own `EnterWorktree` branches from `origin/<default-branch>` or from `HEAD`. Neither is right here, where feature work starts from `develop`.

## Decision

- **The unit of feature work is a git worktree** under `.claude/worktrees/<name>`, branched from `develop`, created with `mise run worktree:new <name>` (`scripts/worktree-new.sh`). See [Work in a worktree](/howtos/work-in-a-worktree).
- **Every port derives from one offset.** The root `mise.toml` gains an `[env]` block: `RZP_BACKEND_PORT`, `RZP_FRONTEND_PORT`, `RZP_DEMO_PORT`, `RZP_DOCS_MEMORY_PORT` and `RZP_DOCS_USER_PORT`, each `base + REZEPTE_PORT_OFFSET * 100`. The main checkout is offset 0 and keeps today's numbers exactly.
- **The offset is assigned when the worktree is created**, to the lowest value free in 1-9, and lives in that worktree's `mise.local.toml`. `worktree:new` derives "free" from `git worktree list --porcelain`, reading each live worktree's own `mise.local.toml`.
- **The live worktrees are the register - there is no separate state file.** Removing a worktree (`git worktree remove`) takes its `mise.local.toml` with it, so the offset is free again the moment the directory is gone. A design with its own registry file can go stale when a worktree is removed by hand; deriving the register from what actually exists cannot.
- **`mise.local.toml` must never be committed.** It is gitignored at every depth, and `.claude/worktrees/` is excluded again on top of that, so the only way it reaches a commit is a deliberate `git add -f`. `mise run check` runs a `guard:local-config` task that fails if `git ls-files` ever reports one tracked.
- **Templates read the offset with `{{ env.REZEPTE_PORT_OFFSET }}`, never `get_env(name=...)`.** This is the one non-obvious trap in the whole design: `get_env` reads only the process environment and silently ignores `mise.local.toml`. Written that way, every port resolves to offset 0 - the code looks correct, `mise run check` stays green, and the feature does nothing until two worktrees actually run at once and collide on the same ports.
- **`REZEPTE_ADDR` keeps its name and stays the service's own configuration surface.** It is what an operator self-hosting Rezepte sets, and it takes an address (`:8060`), not a port. `RZP_BACKEND_PORT` is the dev scheme's variable; the tasks that start the binary translate, `REZEPTE_ADDR=":$RZP_BACKEND_PORT"`. No Go code changes.
- **`.claude/settings.json` sets `worktree.baseRef` to `head`.** The harness's default, `fresh`, branches from `origin/main` - the release branch, well behind `develop`. `head` branches from whatever is checked out, which is correct only when that happens to be `develop`; it is a lesser evil, not a fix. `mise run worktree:new` stays the supported path because it names `develop` explicitly.

## Consequences

- Two, and up to nine, worktrees can run their full stacks side by side without editing anything - `mise run dev`, `mise run e2e` and `mise run //docs/user:screenshots` all resolve to non-overlapping ports automatically.
- A tenth simultaneous worktree has no offset left; `worktree:new` fails with the list of who holds what, which is a machine-capacity problem, not a port-space one.
- Every consumer that used to hard-code a port now reads an `RZP_*_PORT` environment variable instead: `frontend/vite.config.ts`, both Playwright configs, `docs/user/scripts/with-demo.sh`, `scripts/fetch-openapi.ts`, and both docs sites' `package.json`.
- An offset that did leak into the main checkout would shift its ports for reasons nobody can see from the diff - the `guard:local-config` task exists specifically to make that mistake fail loudly at the gate instead of quietly on `develop`.

<Accordions type="single">
  <Accordion title="Alternatives considered">

    - **Offset derived from the worktree name** (`hash(name) % 9`). No state, no script - but two worktrees can hash to the same slot, which is exactly the failure this design exists to prevent.
    - **A registry file** (`.claude/worktrees/ports.toml`). Unique by construction, but it goes stale when a worktree is removed by hand and then hands out an offset that is actually still in use. Deriving the register from the live worktrees gives the same guarantee with no cleanup obligation.
    - **A convention in `CLAUDE.md` only**, with each agent picking a free number by inspection. Least code, but it relies on every agent checking what is taken - an assumption that fails quietly, and exactly when several agents are active, which is the only case that matters.
    - **Renaming `REZEPTE_ADDR` to `RZP_BACKEND_PORT` in the Go config** for full naming symmetry. Rejected: it is the operator-facing configuration of a self-hosted service, documented as such, and changing it breaks existing deployments for a cosmetic gain.
    - **Letting each service pick a free port at startup.** No collisions at all, but nothing is predictable afterwards - the agent, the Playwright config and the Vite proxy would all need to learn the number in advance.

  </Accordion>
</Accordions>
