**Status:** accepted · 2026-09-17 · amended 2026-09-18 (two standalone apps, `dir: 'content'`, user docs on 4001)

## Context

Coding agents need durable context: why things are the way they are, and how to do recurring tasks. Humans need the same in readable form, and later end users need their own docs.

## Decision

- `docs/memory/` and `docs/user/` are both Fumadocs apps on the Next.js static template, each with its own `package.json`, `mise.toml` and Next.js build, and each with its own `content/` directory: `docs/memory/` renders the agent memory from `docs/memory/content/`, `docs/user/` renders the end-user docs from `docs/user/content/`. Their ports are derived from the worktree's offset ([ADR 0018](/decisions/0018-worktrees-and-port-offsets)); `mise run ports` prints them. Not 5000 for either: macOS binds it system-wide to the AirPlay receiver in Control Center, which answers every request with 403, so a dev server can never start there.
- `CLAUDE.md` contains only hard rules and links here for the how and why.
- Memory structure: `decisions/` (ADRs), `architecture/`, `howtos/`, `conventions/`, `roadmap.mdx`.
- Agent routes: `/llms.txt`, `/llms-full.txt`, raw markdown per page under `/llms.mdx/<path>/content.md` - each app serves its own.
- All docs are English.
- Each app defines its own Fumadocs collection scoped to its own `content/`: `docs/memory/source.config.ts` and `docs/user/source.config.ts` both set `dir: 'content'`, so neither app's collection can ever see the other's files.

## Consequences

- Every architecture decision gets an ADR before or with the implementing commit.
- `mise run //docs/memory:check` and `mise run //docs/user:check` each build their own site, so broken MDX in either fails the gate.
- Agents read the MDX files from the repo; the rendered sites are for humans, for the llms routes, and - for `docs/user/` - for end users.
- Two apps rather than one: `docs/user/` carries dependencies the memory app has no reason to hold (Playwright screenshots, a generated API reference), and an independent static export lets it deploy without the internal memory. See [ADR 0013](/decisions/0013-demo-mode-and-docs-pipeline) for the screenshot and API-reference pipeline this enables.
- A collection's `dir` must point at a content-only directory, never a package root. fumadocs-mdx hands chokidar the `dir`, not the filtered file list, so `files` globs filter what fumadocs *processes* and nothing about what the watcher opens: point `dir` at a package root and the watcher takes `node_modules` and `.next` with it, until the dev server dies with `spawn EBADF` or floods the log with `EMFILE`. Hence `dir: 'content'` and the content under `docs/memory/content/`.
