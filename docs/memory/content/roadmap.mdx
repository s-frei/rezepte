## Instance sync

Instance A issues an [API token](/features/api-tokens) scoped to `recipes:read`. Instance B stores its URL and that token and mirrors recipes read-only. Bearer-token authentication exists; what is missing is the `/api/v1/sync/*` endpoints themselves.

## Shared shopping lists

Lists, sharing them, live updates and a shopping mode exist - see [Shopping lists](/features/shopping-lists). Ahead:

- **API and MCP.** Token scopes `lists:read` and `lists:write`, and MCP tools to read lists, add a recipe at servings and add, tick and remove items. The list endpoints then take tokens as well as sessions.
