<Callout type="warn" title="Hard rule">

  Never hand-edit `docs/user/content/api/reference.mdx`. It is generated; any manual change is overwritten by the next regeneration.

</Callout>

## What the task does

```bash
mise run //docs/user:openapi
```

1. Builds the Go binary (`//service:build`).
2. `docs/user/scripts/with-demo.sh` starts it with `--demo` on `:8070` against a throwaway data directory and waits for `/healthz`.
3. `scripts/fetch-openapi.ts` fetches `/api/v1/openapi.json` from that instance and writes `docs/user/public/openapi.json`.
4. `scripts/generate-api.ts` reads `public/openapi.json` (no running server needed for this step) and writes `content/api/reference.mdx`: one section per huma tag, one subsection per operation with its parameters, request body and response table, then a `## Schemas` section with a property table per named schema. Tags, operations and schemas are all sorted, so the diff is deterministic.
5. `with-demo.sh` stops the binary and deletes the data directory.

Run it whenever an endpoint, parameter or schema changes - see [Keep the user docs in step with the UI](/memory/howtos/update-user-docs). CI runs the same task and then `git diff --exit-code`, so a forgotten regeneration fails the build, not just a review.

## Extending the generator

`scripts/generate-api.ts` hand-rolls a small OpenAPI 3.1 reader (`Schema`, `Parameter`, `Operation`, `Document` types at the top of the file) rather than depending on `fumadocs-openapi` - see [ADR 0013](/memory/decisions/0013-demo-mode-and-docs-pipeline). When huma starts emitting a schema shape the generator does not render correctly (a new `oneOf`/`anyOf`, `additionalProperties`, or a `format` the reference should call out):

1. Add the missing field to the `Schema` type.
2. Extend `typeOf()` (how a schema renders as a type, e.g. `string (uuid)` or a `[link](#anchor)[]`) or `constraints()` (the plain-English list appended to a field's notes, e.g. `length 1–120`) to handle it.
3. Run `mise run //docs/user:openapi` and read the resulting diff in `content/api/reference.mdx` to confirm the new shape renders sensibly before committing.

`SCREENSHOT_BASE_URL` also affects this task: `fetch-openapi.ts` reads it (default `http://localhost:8070`) to find the running instance - see [Add a screenshot](/memory/howtos/add-screenshot) for when to override it.
